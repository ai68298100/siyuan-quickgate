# AI 路线规格（G3 · §18.4 R126 · v0 规格）

> 目的：在 schema（C1/C2/证据信封）与安全门合同已就绪的前提下，为 AI 能力定义**依赖顺序、门禁、降级与退出条件**；验收 = 模板和场景不得先于 schema/安全。
> 状态：v0 规格——纯规格层（不实现、不接模型、不改 AI 配置）；实现全部绑定 G2 样板完成之后。

## 1. AI 顺序（R126-G3 第一条：依赖重排定版）

```
[已完成前置] C1 结果合同 ✓ / C2 上下文合同 ✓ / 证据信封合同 ✓ / 安全门合同 ✓ / MCP 只读工具 ✓
     ↓
G3-① 只读研究/查询解释闭环（首个；evidence-envelope 必须承载输出）
     ↓
G3-② 捕获草稿（写前确认；evidence envelope + draft 对比）
     ↓
G3-③ 低风险写入（checkin.record 级；C1 状态语义 + 确认绑定）
     ↓
G3-④ Agent 低风险写 / 模板生成 / 场景包（每步重过安全门矩阵）
```

不变量：任何阶段不得跳过前一阶段的证据门禁；安全门（safety-gate-contract）在全阶段生效且不可被 prompt 覆盖。

## 2. 只读优先门（G3-① 的验收）

只读闭环 = 用户问 → AI 引用思源内容作答 → 信封标注来源与截断 → 用户可点开原文核对。门禁条件：

1. 输出走 evidence-envelope（缺源显式 unknown，禁止美化）；
2. 工具面只开放只读 MCP 工具（现 13 个即可满足——无需新开发）；
3. 错误回答的代价可逆（不动数据）。

**未通过本门之前：捕获草稿/写入/Agent 写全部不开放**（包括 MCP 写工具的 LV_MCP_WRITE）。

## 3. 模型角色与降级（R126-G3 第三条）

| 角色 | 用途 | provider/modelId | 缺模型时 |
|---|---|---|---|
| agent | 理解/规划/草稿 | 用户自配（快门不自带——红线 4） | 功能入口隐藏（不置灰，直接不出现） |
| embedding/rerank | 检索排序 | 用户自配；缺省 = 退化到 SQL/关键词 | 只读闭环降级为纯查询 |
| decision | 自动判断类 | **禁用自动化决策**（需人在环） | 不适用 |
| image | 图片理解 | 不在首批范围 | — |

降级铁律：**不静默换远端**——配置了哪个用哪个；没配置就走非 AI 等价路径（手动等价路径合同 §R125-G2）。

## 4. 版本漂移（G3 第四条）

| 变化源 | 触发 | 动作 |
|---|---|---|
| 模型 provider/modelId | 配置变更 | 该配置下的首个调用跑 fixture 集（固定输入→断言关键输出特征） |
| 提示词版本 | prompt 文件哈希变化 | 同上 + promptVersion 入 evidence-envelope |
| 工具 schema | ops 面变化（consistency test 已强制） | MCP 工具集随之变化，重跑 accept |
| 思源版本 | 内核升级（如 3.8.6→3.9） | verify-restart 复测批 + bundle 证据法复核 DOM 假设 |

旧会话绑定旧版本：会话内记录 promptVersion/modelId（envelope.generatedBy），回放解释以记录为准。

## 5. 同一审计链（G3 第六条）

任何入口产生业务动作都必须落在同一链条：`intent → plan → command(id) → receipt → 业务实体`。

- 现状：Quicker/CLI/MCP 已同链（信封 id 贯穿 + 审计日志）；
- AI 草稿（G3-②起）：草稿本身入审计（draft_id），转为正式写入时沿用 C1 确认绑定；
- 验收方法：同一次业务行为从四个入口分别触发，审计里四条记录可关联回同一 intentId（planned，依赖 C2 Intent 中枢）。

## 6. 同意与删除（G3 第七条）

| 项 | 规则 |
|---|---|
| 同意 | contains-personal 数据出模型前必须一次性显式同意（拒则 local-only 降级：AI 只处理 local 模型或不出网路径） |
| 撤回 | 撤回同意后：AI 入口隐藏（同缺模型降级）；已外发数据无法撤回——诚实呈现 |
| 保留期限 | 由模型服务商条款决定；快门侧不缓存 prompt/原文（prompt 即用即弃，除非用户显式开启历史） |
| 导出/删除 | 覆盖范围=快门本地（审计/缓存可删）；远程侧提供服务商入口链接，不代删 |
| 隐私说明 | 文档描述必须与实际数据流一致——每次新增外发路径都要过安全门矩阵 |

## 7. 可访问性（G3 第五条）

AI 交互验收必须覆盖：流式中断（半截回答可重发）、长响应折叠（可展开）、纯键盘完成全流程、焦点不丢失、屏幕阅读器可读（语义标注）、**无模型替代入口永远存在**（手动等价路径合同）。确认流程不依赖鼠标或视觉细节。

## 8. 退出条件（G3 第八条）

每个 AI 场景上线时同时登记退出判据，任一命中即降级或归档：

| 判据 | 示例阈值 |
|---|---|
| 不值得自动化 | 手动 < 10s 且频率 < 1 次/天 |
| 证据不足 | 连续 N=5 次输出 unknown/需人工全部重做 |
| 成本过高 | 单次 token 成本 × 频率 > 手动时间折价 |
| 误判不可接受 | 涉及删除/外发/钱的场景误判率 > 0 |

连续失败后自动降级（入口隐藏）并登记归档记录——**AI 场景可以有尊严地死掉**。
