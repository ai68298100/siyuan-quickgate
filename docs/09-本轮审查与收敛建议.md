# 本轮审查与收敛建议（2026-10-01）

## 审查范围与结论

本目录目前是设计资料集合：README、TODO、8 份设计文档、菜单模板和动作库快照；没有 quickgate 源码、Quicker 动作导出包、`package.json`、测试脚本、CI 或 Git 仓库。因此本轮只能做静态审查，不能声称插件已经可安装或 `check/test/build` 已通过。

已验证：两份 JSON 均可严格解析；动作快照有 239 条记录且 `code` 唯一；本轮新增 R1 收敛项后 TODO 有 230 条，其中 228 条未完成、2 条已完成（新增前基线为 209 条）。动作库页面的原始条目约 253 个，239 是本地快照去重后的数量。

第一性结论是：当前设计把“小驴快门”过度收窄成 Quicker 网关，而用户实际需要的是**小驴生态联动中枢**。Quicker 应是外部客户端之一，快门还要服务雷切、打卡、拾遗、人脉、管家、闪卡、考试和后续插件。

## 目标边界

快门中枢只消费公开注册能力和公开桥方法，不读其他插件私有存储。共性能力分为：

| 能力 | 作用 | 典型消费者 |
|---|---|---|
| `registry.*` | 插件、版本、能力、就绪和健康状态 | 管家、诊断、超级面板 |
| `commands.*` | 公开命令的发现、确认、执行和审计 | Quicker、管家、雷切 |
| `context.*` | 编辑器、工作区和前台场景快照 | 拾遗、管家、Quicker |
| `events.*` | 白名单本地事件及 schema/幂等约束 | 打卡、闪卡、考试、拾遗 |
| `workflow.*` | 受控的跨插件组合流程 | 管家、超级面板、Quicker |
| `diagnostics.*` | 统一健康报告和排障信息 | 所有插件和用户 |

七款插件的第一批职责映射如下。具体方法名必须以各插件仓库的公开契约为准，表中“方向”不等于已经存在的 API。

| 插件 | 联动方向 |
|---|---|
| 小驴雷切 | 工作上下文、导航和受控写入 |
| 小驴打卡 | 事项、记录、汇总和打卡事件 |
| 小驴拾遗 | 捕获、整理和回写 |
| 小驴人脉 | 人员搜索、收编和互动记录 |
| 小驴管家 | 聚合面板、流程入口和健康状态 |
| 小驴闪卡 | 到期查询、制卡和复习入口 |
| 小驴考试 | 题库、考试会话和成绩摘要 |

本机仓库抽查后的可用性分层：雷切已有工作上下文/命令/组件注册能力；打卡已有稳定的 v5 公开桥和能力协商；人脉已有公开桥。管家、闪卡、考试仍处于设计或脚手架阶段，不能把规划中的 RPC、事件或 Gateway 当作现成契约；拾遗仓库本轮未定位，暂不能验证公开 API。中枢应据此分阶段接入：已稳定的能力进入首批 adapter，设计态插件只进入 manifest/诊断，不进入默认工作流。

| 插件 | 当前 manifest/状态（本轮抽查） | 中枢接入等级 | 事实边界 |
|---|---|---|---|
| 小驴雷切 | 0.40.0，已发布 | stable | 工作上下文、Home module、Quick Action、Agent 能力；不持有打卡/联系人业务主数据 |
| 小驴打卡 | 18.8.0，已发布；公开 API v5 | stable | `whenReady`/能力协商/记录幂等已可用；v4 getter 只作兼容回退 |
| 小驴人脉 | 0.1.0，已发布；公开 bridge v1 | stable | 人员搜索、收编、互动记录；写入必须走 bridge |
| 小驴管家 | 0.1.0，开发中且 disabledInPublish | design | home RPC/归档关联仍是规划，默认模块也需要成熟度收敛，暂不作为数据源 |
| 小驴闪卡 | manifest 0.5.0，README 仍写 0.2.0，开发中且 disabledInPublish | design | Gateway 和 `lv-cards:*` 事件仍在待办，不能当作现成外部契约 |
| 小驴考试 | 0.1.0，设计/脚手架阶段且 disabledInPublish | design | 尚无稳定生态 bridge/event；题库和作答数据留在插件内部 |
| 小驴拾遗 | 本机未定位仓库或 manifest | unlocated | 未有可验证公开 API，只能显示能力缺失诊断 |

版本以各仓库当前 `plugin.json` 为准；README 与 manifest 漂移（当前已知闪卡）要在对应插件发布前修正，中枢不能自行替插件声明版本。

边界判断：雷切负责聚合视图、上下文和动作路由；管家未来负责家庭台账与提醒数据；闪卡负责复习与卡片统计；考试负责题库、作答和错题；拾遗负责捕获与归档。中枢编排这些能力，但不复制任何业务数据库，也不把雷切或管家变成全生态数据总线。

## 阻断项（完成前不进入 M1/M2）

1. **桥队列可靠性**：当前“读整文件→异步执行→覆盖写剩余行”的方案，在消费 A 期间追加 B 时会丢 B。M1 必须改为每命令独立文件、可原子认领的队列，或先实证双方可参与的统一锁；验收要覆盖消费期间追加命令不丢失。
2. **主路径统一**：P1 动作和菜单模板必须走快门语义化 op；旧插件桥只作为无快门兜底。打卡、人脉不应同时存在两套默认路由。
3. **回执时间语义**：普通命令可用短等待，但 `commands.run` 的确认窗口最长 30 秒。客户端必须按 op 使用等待策略，或返回 `pending` 后异步取回；超时后禁止自动生成新 id 重试，并测试迟到副作用。
4. **幂等持久化**：去重不能只靠最近 200 条内存缓存；需要持久化/从回执恢复，且 `externalRef` 必须由输入信封 id 稳定派生。
5. **单飞轮询**：禁止 `setInterval` 在慢 HTTP 或确认任务期间重入；改为一次 poll 完成后再调度下一次，并把批次上限、退避和关闭状态纳入单测。

## P1 收敛项

- 为七款插件定义版本化 capability manifest：`pluginId`、版本、协议版本、能力名、`whenReady`、`health`、公开方法和错误状态。
- 固化 `registry.*`、`context.*`、`events.*`、`workflow.*`、`diagnostics.*` 的最小契约，缺失能力返回结构化 `unsupported`，不阻断宿主启动。
- 给菜单模板建立 discriminated-union schema：统一 `then.v` 结构、`profile`、逐项 capability gate，并用校验脚本阻止错误模板进入动作包。
- SY-12 使用明确的日期边界和日记笔记本过滤；AI→SQL 采用单语句 `SELECT/EXPLAIN` 白名单、强制 `LIMIT`、拒绝注释/多语句和写操作，补齐请求/响应样例。
- 调试日志默认只记录端点元数据、状态和耗时；正文、Token、个人路径和用户内容必须脱敏或关闭。
- 将协议版本、退避上限、端点数量、动作快照数量和 M0 spike 清单集中维护，避免 10s/30s、v1.1/v1.2、253/239 等漂移。

## P2 可选项

广播/v2 同步通道、第三方适配器 manifest、手机入口、生态工作流市场和更多插件适配器，均在 P0/P1 契约稳定并完成真实联调后再做。它们不能替代队列可靠性、能力协商和诊断基础。
