# 调研报告：Quicker × 思源笔记联动方案

> 调研日期：2026-10-01 · 环境：Windows 11 · Quicker V2 · 思源 v3.8.x（内核端口当时误录 1568——R21 实证为默认 6806，下文涉及端口处以本注为准）
> 结论先行：**Quicker → 思源走内核 HTTP API（成熟；动作库页面原始条目约 253 个，本地快照去重 239 个）；思源 → 外部客户端走统一中枢契约。小驴快门同时承担小驴生态联动中枢和外部网关，先统一能力注册、健康检查、上下文、事件与工作流，再把 Quicker 接入同一套公开桥。**

---

## 1. 全部可用通道盘点

双向共 6 条通道，按可靠性排序：

| # | 通道 | 方向 | 成熟度 | 说明 |
|---|---|---|---|---|
| 1 | **思源内核 HTTP API** | 外部客户端→思源 | ★★★ 官方 | `http://127.0.0.1:<端口>` + Bearer Token，本机端点表 548 个条目。Quicker「HTTP 请求」模块直连，无跨域问题（桌面程序不受 CORS 约束） |
| 2 | **Quicker 内置 HTTP API** | 思源/手机/任意程序→Quicker | ★★★ 官方(V2) | `POST http://127.0.0.1:668/api/exec` + Bearer Token，可运行动作、传参数、等待返回值；同页还开放 WebSocket 服务。**注意：未开放跨域**，浏览器内 fetch 受限，桌面脚本/快捷指令不受限 |
| 3 | **Quicker 动作内 HTTP 服务器模块** | 任意→Quicker | ★★ 官方 | 动作运行期间在本机开临时 HTTP 服务，路由由子程序处理（GET/POST/PUT/DELETE + JSON），适合「思源插件通知 Quicker 做事」的反向通道 |
| 4 | **siyuan:// URL 协议** | Quicker→思源 | ★★★ 官方 | `siyuan://blocks/<块ID>` 打开并定位块；Quicker「打开网址」模块或 `run` 模块调用 |
| 5 | **内核文件 API / 文件系统** | 双向 | ★★★ | Quicker 可直接读写工作空间 `data/` 下文件（也可经 `/api/file/putFile`、`/api/file/getFile` 走内核）；小驴插件的 petal 存储就在这里。**这是深度联动的关键通道** |
| 6 | 剪贴板 / 窗口消息 / UIA | 兜底 | ★ | Quicker 的剪贴板、sendkeys、UIAutomation 模块。只在 API 不可用时兜底 |

### 1.1 通道 1 的关键细节（Quicker HTTP 请求模块实测文档）

- 支持 GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS；请求体类型选 **JSON**；Content-Type 走专用「内容类型」参数（不要写进请求头）。
- 响应自动分变量保存：是否成功 / 状态码 / 响应头(词典) / Cookies(词典) / 文本结果。思源返回 `{code, msg, data}`，`code=0` 为成功。
- 变量插值用 `{变量名}`，C# 表达式用 `$=` 前缀（如 `$= JsonConvert.SerializeObject(new { id = {块ID} })`）。
- 超时默认 100 秒；思源在本地，建议改成 10 秒并勾选「失败后停止」。
- JSON 解析用 `jsonextract` 模块或 C# 表达式（`Newtonsoft.Json`）。

### 1.2 通道 2 的关键细节（Quicker 内置服务）

- 开关位置：Quicker 设置 → 软件连接 → HTTP / WebSocket 服务；默认端口 **668**，可选 HTTPS（`lan.quicker.cc` 证书）。
- `POST /api/exec`：`operation` 支持 `copy / paste / inputtext / input / sendkeys / open / action`。
  - `action` 可运行指定动作、传输入参数，`wait: true` + `maxWaitMs`（≤60000）时**同步等待动作完成并取回返回值**（结果在 `result.data`）——这一条让「外部程序调用 Quicker 并拿到结果」成为一等能力。
- 权威格式见官方文档：[HTTP 与 WebSocket 服务](https://docs.getquicker.net/v2/features/http-websocket/)。请求体上限 32KB；**未开放跨域**——思源插件渲染进程里能否直接 fetch 需实测（Electron webSecurity 配置而定），实测不通就走通道 3 或 5。
- 典型用途：iOS/安卓快捷指令、语音助手、HA 等远程触发本机 Quicker 动作（动作库里「Siyuan速记」就是这一模式的前身：手机打字 → PC 实时入库思源）。

### 1.3 Quicker 触发器盘点（动作怎么被唤起）

同一个动作可同时挂多种入口（[快速触发概览](https://docs.getquicker.net/v2/features/triggers/)）：

| 触发方式 | 联动用法 |
|---|---|
| 动作面板按钮 + **场景** | 给 SiYuan 进程建专属场景：思源前台显示思源专属动作页 |
| 全局/程序快捷键（动作热键） | 全局唤起「快速捕获」；思源前台绑定「快查」 |
| 划词工具条 | 选中文字浮出「摘录到思源」 |
| 文本指令 | 输入 `sy`+空格 触发快查、`jl`+空格 记一笔 |
| 高级鼠标（中键/侧键/手势/轮盘） | 侧键唤起雷切式切换 |
| PowerKeys / 按键双击 | 如连按 `Shift` 唤起捕获 |
| **网页动作按钮**（浏览器扩展） | 匹配 `localhost:1568` 或思源域名时在网页上显示动作按钮 |
| 命令行 / `quicker://` 协议 / `/api/exec` | 外部程序、开机脚本、手机快捷指令触发 |
| 动作内 HTTP 服务器模块 | 临时服务端口被调用时进入子程序分支 |

### 1.4 其他关键模块

`jsonextract`（解析内核响应）、`jsscript` / C# 脚本（复杂组装）、`userinput`/`userselect`/`showmenu`（交互）、`openurl`（siyuan://）、`readfile`/`writetextfile`（petal 桥文件）、`statestorage`（动作间共享 Token 等状态）、`runaction`/子程序（复用）、`notify`/`msgbox`（打卡结果提醒）、`waitclipboardchange`（剪贴板监听）。

> 付费说明：免费版可正常开发和使用基本动作，部分高级模块与动作数量有限制，以官方为准。

## 2. 动作库现状：页面约 253 个，快照去重 239 个

Quicker 动作库的 SiYuan 分类页面采集时显示约 **253 个原始条目**；本仓库快照经 code 去重后为 **239 条**（采集日期 2026-10-01）。代表性作品：

|---|---|---|
| 快摘 | 寒Orz | 划词/链接/图片 → Markdown → 内核 API 追加到指定文档（**通道 1 的标准范式**） |
| 快查 | 寒Orz | SQL 搜索思源内容并跳转（`/api/query/sql` + `siyuan://` 定位） |
| Siyuan速记 | 何舜人 | iOS 快捷指令 → PC 实时写入思源（**通道 2 的标准范式**） |
| 添加豆瓣信息到思源数据库 | — | 抓取外部数据 → 写入思源**数据库(AV)**（证明 Quicker 写 AV 可行，与人脉库同机制） |
| 标题一键制卡 / 2Anki / Zotero批注 / 智能备份 / 标题编号 | — | 各种读写与批处理 |

**结论**：内核 API 路线完全成熟，可直接抄作业；但**没有任何一个动作对接小驴生态**——通用动作是「写进思源」，小驴动作是「调用插件能力」，这是空白也是价值点。

## 3. 小驴七插件的集成面与缺口

现有七款插件的能力都运行在思源渲染进程内；外部客户端无法直接调用窗口内 JS 是共同缺口。能力应由中枢统一发现和转发，插件不再各自重复实现外部桥：

### 3.1 小驴打卡（siyuan-checkin，当前 manifest 18.8.0；以公开 API v5 契约为准）

- 公开桥：`window.siyuanCheckin`，协议名 `siyuan-checkin`，API **v5**（能力协商式）。
- 能力面：`items.read/query`、`events.read/range.read/record/record.batch`、`summary/analytics/metrics.read`、`export.json/csv`、`focus.adapters`。
- 写入语义：`recordEvent({itemId, value, unit, source, externalRef, note})`，**`source+externalRef` 幂等去重**，批量上限 200；外部来源不得伪装 `manual`。
- 缺口：无文件/HTTP 摄取通道，外部程序（含 Quicker）无法调用。

### 3.2 小驴人脉（siyuan-contacts）

- 公开桥：`window.LvContacts`，protocol 1，能力 `searchPeople / getPerson / ensurePerson / recordInteraction`。
- 数据契约（见插件 `docs/DATA-CONTRACT.md`）：联系人=文档+数据库行，四锚点 ID（notebookId/hostDocId/dbBlockId/fieldMap）固化在 petal 的 `contacts-settings.json`；数据库读取一律 `renderAttributeView`（AV 无 SQL 表）；互动事件在插件自管 JSON，`source+externalRef` 幂等 + 墓碑。
- **旧方案观察**：曾考虑让 Quicker 只读 `contacts-settings.json` 拿锚点；这仍属于插件私有存储，不纳入中枢主路径。
- **当前边界**：Quicker 和其他客户端统一走快门 `contacts.search/ensure/interaction`；绝不绕过插件直接写 AV 行或互动事件 JSON，避免与插件内存态互相覆盖。
- 缺口：同打卡，外部无入口。

### 3.3 小驴雷切（siyuan-speed-switch，当前 manifest 0.40.0；以公开能力描述为准）

- 思源 v3.8.4+ 的 `addAgentCapability` 注册了 **11 项能力**：只读（navigation-state、search-documents、workspace-context 等）+ 受控导航（open-document(s)）+ **受控写（create-document、append-to-journal、update-task-status，强制确认，30s 超时拒绝）**。
- 缺口：Agent 能力由思源内置 Agent 调用，外部程序无入口；但其受控写语义（计划→确认→回执）正好可以复用为桥的执行语义。

### 3.4 其余插件的中枢接入面（待各仓库公开契约确认）

| 插件 | 适合由中枢统一提供的能力 | 首批联动方向 |
|---|---|---|
| 小驴拾遗 | 捕获/整理/回写能力 | Quicker、手机或其他插件提交内容后统一进入拾遗流程 |
| 小驴管家 | 工作台、日程/任务聚合、插件健康状态 | 作为组合流程入口，不重复实现每个插件的业务逻辑 |
| 小驴闪卡 | 到期卡片查询、制卡、复习入口 | 面板展示到期数，跨插件流程把会议/阅读结果送入制卡 |
| 小驴考试 | 题库/考试会话/成绩摘要 | 统一启动考试、回写复习或任务事件 |

上表是**集成方向，不是已确认 API**。实现前各插件需要提供版本化 capability manifest、`whenReady`、公开方法和失败状态；中枢只消费这些公开能力，不读取私有存储。

### 3.5 中枢应提供的共性能力

1. **能力注册与健康检查**：按插件 ID、版本、能力名、协议版本和就绪状态注册，统一显示缺失/停用/不兼容原因。
2. **命令与上下文**：统一命令枚举/执行、当前编辑器与工作区快照，供 Quicker 和其他小驴插件复用。
3. **事件与工作流**：发布受限的本地事件（如捕获完成、打卡完成、卡片到期），组合多个插件的只读查询和受控写入；每一步有确认、超时和幂等键。
4. **诊断与兼容**：一处报告插件版本、能力协商、桥状态和最近失败，宿主升级后能力降级而不是阻断启动。

### 3.6 缺口结论

七款插件共享同一个中枢补丁：先在思源内建立公开能力注册和联动契约，再由 Quicker、手机、脚本等外部客户端选择 NDJSON 或后续同步通道。已有插件桥方法只做适配，不新造写路径；无中枢时才使用 [02-小驴桥协议-v1.md](02-小驴桥协议-v1.md) 的直连兜底。

## 4. 方案设计：三层递进

### Tier 1 立即可做（零插件开发，1 天内可用）

全部基于通道 1/4，动作清单见 [03-动作蓝图.md](03-动作蓝图.md)：

1. **快速捕获**（全局快捷键/PowerKeys）→ 输入一句 → `appendDailyNoteBlock` 追加到今日日记（端点自带「不存在则创建」）
2. **划词摘录**（划词工具条）→ 选中文本+来源 → `appendBlock` 到收集箱文档，带 `> 引用` 与来源链接
3. **思源全局快查**（文本指令 `sy`）→ `fullTextSearchBlock`/SQL → 菜单选结果 → `openurl` 打开 `siyuan://blocks/<id>`
4. **打开今日日记**（侧键/快捷键）→ SQL 找今日日记 → `siyuan://` 打开
5. **剪贴板图片入库**（HTTP 模块 Multipart）→ `/api/asset/upload` → 返回链接插入文档
6. **思源前台场景**：以上动作进 SiYuan 场景页，思源前台才有专属面板

### Tier 2 深度联动（先做中枢骨架，再做适配器）

- 中枢侧：能力注册、健康检查、命令/上下文/事件/工作流基础契约；各插件只提供公开 adapter，不各自复制轮询器。
- 外部侧：Quicker 通过公共子程序「LV·发命令」/「LV·取回执」接入；其他客户端复用同一契约。
- 落地动作：
  - **一键打卡**：经中枢 `checkin.items` / `checkin.record` / `checkin.summary`；`externalRef` 由输入信封 id 派生，重试不重复
  - **记人脉互动**：经中枢 `contacts.ensure` / `contacts.interaction`；中枢负责能力协商和失败回执
  - **专注打卡**：Quicker 计时结束自动 recordEvent（幂等防重复）
  - **追加今日日记（雷切确认流）**：走雷切 `append-to-journal` 语义，保持全端一致

### Tier 3 平台级（锦上添花）

- **手机 → 本机**：iOS 快捷指令/安卓 HTTP Request → `POST /api/exec (operation=action)` 触发「快速捕获」，甚至 `wait:true` 取回查询结果（复刻并超越 Siyuan速记）。
- **雷切工作台挂 Quicker 卡片**：雷切组件面板有第三方接入组件机制（home-widget-snapshot），可做一个「Quicker 动作」组件：点击 → 经桥 op 调 Quicker（`/api/exec` 或 httpserver 模块），让雷切成为动作统一外壳。
- **思源内触发 Quicker**：思源文档里放 `quicker://` 链接、或插件经桥反向通知 Quicker（通道 3/5）。CORS 需实测后再定首选。

## 5. 安全与工程边界

1. **Token 保护**：思源 Token 等同工作空间完全读写权。动作里不要明文扩散；Quicker 动作用「用户配置」项或 `readfile %APPDATA%\siyuan\env` 读取。把动作分享到动作库前必须清掉个人 Token（动作库现有思源动作都要求用户自填）。
2. **内核端口**：本机是 1568 不是默认 6806，动作配置做成用户可改。
3. **幂等**：所有写入型桥 op 必须带稳定 externalRef（Quicker 生成 uuid/日期键），重试不产生重复数据——打卡/人脉已有此语义，桥协议强制沿用。
4. **写放大**：Quicker 轮询建议 ≥3s 间隔且仅在思源运行时；命令文件处理完即清空，防止无限增长。
5. **CORS 现实**：思源渲染进程 fetch `127.0.0.1:668`（Quicker 服务）未开放跨域，思源→Quicker 方向先走通道 3/5，`/api/exec` 留给桌面脚本与手机。
6. **多工作区**：petal 桥文件按工作空间隔离，天然不串数据；Quicker 动作配置里工作空间路径可选项化。
7. **内核索引延迟**：写入后立刻查询可能读不到（SQLite 异步建索引），链式操作一律用写接口返回的 ID，不要回头 SELECT。
