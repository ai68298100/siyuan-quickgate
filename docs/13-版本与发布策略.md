# 版本与发布策略（三线分记）

> 集市暂缓期的一份口径，避免版本号互相污染。三线各自独立演进，互不绑定。

## 三条版本线

> 当前值同步（R69·文档，2026-10-04）：快门 **v0.7.3**（tag 已推，正式 Release 已去 prerelease）；桥协议 v1.1；menu schema v1。详细版本锚点见实现仓库 CHANGELOG 与本目录 REPO-MAP.md。

| 线 | 载体 | 当前 | 规则 |
|---|---|---|---|
| **快门插件** | `siyuan-quickgate/plugin.json` + GitHub Release | v0.7.3（正式版） | SemVer：桥协议/契约破坏性变更升大版本前的 0.x；每版必附 package.zip + SHA-256 + SBOM + 手动安装说明；发布自查门 check:release/check:version 已入 CI |
| **桥协议** | docs/02（人读）+ quickgate `docs/contracts/quickgate-api-v1.json`（机器） | v1.1（信封 v1） | 信封字段破坏性变更才升 `v`（当前恒 1）；能力新增只追加 op，不改信封；contracts JSON 是机器事实源，文档跟随；一致性检查=protocol-consistency-2026Q4 |
| **动作包** | quicker-actions/（导出文件）+ 面板 menu JSON | menu schema v1 | menu JSON 结构变更升 `version` 字段并同步 validate-menu；动作导出文件在 quicker-actions/README.md 登记版本对应表；参考件 27 脚本 csc 编译门 |

## 发布节奏

1. **快门**：功能批次 → push（CI 全绿）→ tag `vX.Y.Z` → prerelease（package.zip）。正式 Release（去 prerelease 标）与集市上架共用 §8 门槛。
2. **动作**：Quicker 编辑器搭建完成后导出归档；每次导出更新 quicker-actions/README 对应表。集市分享延后。
3. **协议**：只随快门发版携带；协议变更必须在 DECISIONS.md 有对应 D-xxxx 记录。

## 当前发布前检查（每次 tag 前过一遍）

- [ ] `pnpm run check && pnpm test && pnpm run build` 全绿
- [ ] CHANGELOG 有本版条目；README 徽章版本同步
- [ ] plugin.json 版本 = package.json 版本 = index.ts PLUGIN_VERSION
- [ ] package.zip 内无桥运行数据/凭据（.gitignore 已挡，抽查 zip 内容）
- [ ] Release notes 含手动安装说明与已知边界
