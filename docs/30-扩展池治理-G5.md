# 扩展池治理与退出规则（G5 · §18.8 R130 · v0 规格）

> 目的：为不断膨胀的调研/候选池定规则——什么能晋升、什么该降级、什么被锁定、并发多少、多久复盘。
> 状态：v0 规格——治理规则的终章；与前五份合同共同构成完整的自我治理体系。

## 1. 晋升规则（R130 第一条：五级管道）

```
研究池（§13~§22）→ 契约（docs/contracts/）→ 样板（G2 纵向）→ 实现（代码）→ 真机（E4）→ 发布（E5/公开）
```

| 晋升 | 必要条件 | 反例（禁止） |
|---|---|---|
| 研究→契约 | 有明确对象形状（对照已实现或上游源码） | 纯想象的功能描述进契约 |
| 契约→样板 | 安全门矩阵可过 + 手动等价路径存在 | 写风险不明就开写 |
| 样板→实现 | G2-首成功（用户确认） | 代码存在=完成 |
| 实现→真机 | 静态/单测证据 + verify-restart 相关项 | 只过 CI 就发 |
| 真机→发布 | release-evidence 七项 + 事实表同步 | 未验证能力进"已支持"宣传 |

**铁律：没有证据的功能不能只因讨论次数上升**——讨论热度是需求信号，不是证据。

## 2. 降级规则（R130 第二条）

| 触发 | 动作 |
|---|---|
| 连续无用户需求（两个季度未出现在使用记录） | 移入归档节，主清单不再计数 |
| owner 不明确（无插件/无人认领能力） | 标 `blocked:owner`，不得进实现 |
| 维护成本超预算（预估 > 现有全部维护投入） | 拒绝立项或拆小 |
| 上游能力消失（思源/Quicker API 移除） | 标 `replaced/archived`，链接替代方案 |
| 风险不可接受（安全门矩阵过不了） | 直接归档，附原因 |

归档保留全部历史链接（TODO 条目不删除、只移节 + 状态标注）。

## 3. 自动化延后锁定（R130 第三条）

规则引擎（R82）、后台触发、跨插件循环**锁定在 C5/C6 有真实闭环证据之后**：
- 一次性 `workflow.plan/execute` 不等于持久自动化——后者引入调度/重试/权限的全新故障面；
- 解锁条件：G2-最小可用 + 至少一个"重复手动操作"的真实记录（§7 表中出现 ≥3 次同类操作）。

## 4. 插件接入限额（R130 第四条）

- 每轮只选**一个稳定插件 owner** 做联动深化；
- 缺公开契约的拾遗/考试/管家保持 design/unlocated——**不以 manifest 声明代替可调用接口**（C3 合同 declared≠available）；
- 新插件接入前置：上游公开桥文档 + 一次真实能力探测（loadPetals/窗口桥）。

## 5. 调研 WIP（R130 第五条）

- 研究并发上限：**同时 ≤2 个调研主题**（当前 R80~R160 的存量池冻结，只消化不扩池）；
- 新增调研必须**关闭一个旧问题**或说明新增证据来源——纯"再想想"不立项；
- 调研产物必须落到 docs/NN 文档 + TODO 条目，不留在对话里。

## 6. 季度复盘（R130 第六条）

每季度一次（下次：2027-01），固定议程：
1. 规范主线 C1~C8 覆盖复核（snapshot byMainline 对比）
2. 依赖环与 planned 清单清点（contracts 中标注的 planned 逐个过）
3. WIP 执行情况（样板是否按门禁推进）
4. 用户证据盘点（G2 §7 表/使用记录）
5. 上游变化（思源/Quicker/小驴插件新版本——bundle 证据法+manifest 校准）
6. 归档项复核（降级条目是否有复活证据）
