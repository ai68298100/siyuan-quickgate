# 发布与证据维护（G6 · §18.7 R129 · v0 规格）

> 目的：把用户证据、文档事实、兼容矩阵与发布维护收敛为一份长期维护规格；验收 = 无一处单独宣传未验证能力。
> 状态：v0 规格——基于 release-evidence-contract（发布前七项）向"发布后长期维护"延伸。

## 1. 文档事实表（R129-G6：单一事实源）

所有对外文档的**能力/版本/证据声明**引用同一张事实表（`docs/contracts/` 七份合同 + 本文件 §2 兼容矩阵），不允许各文档自行措辞：

| 文档 | 引用方式 |
|---|---|
| README ×2 / api.md / ROADMAP | 版本徽章+状态节（已对齐，R64/R65 流程） |
| 动作说明（quicker-actions/） | 引用 docs/25 样板规格 + 结果卡 |
| MCP schema（src/mcp/tools.ts） | ARGS 表即事实表（契约测试强制） |
| Agent skill（未来） | 引用 C3 能力注册表合同 |
| 发布说明 | release-evidence §2 声明规则 |
| Quicker 分享页 | 链接 GitHub README，不复制能力清单 |

规则：能力变化 → 先改事实表（合同/snapshot）→ 再同步各文档（五文档面 checklist）；顺序反了就是漂移（R52/R56 教训）。

## 3. 发布门禁 checklist（R129-G6：单一清单，引用既有合同）

合并自 release-evidence-contract §1 七项 + 本表，最终版：

1. 版本四处一致（脚本可查）
2. `npm run accept` 全绿
3. 真机数据集（verify-restart；未过项显式声明 → pre-release）
4. 兼容矩阵 §2 更新（新验证项入表）
5. 凭据扫描零命中
6. dist 白名单 + 无 storage/私有数据
7. 七文档面同步（CHANGELOG/PROGRESS/README×2/api.md+ROADMAP/事实表）
8. 已知缺陷与功能并列发布
9. 回滚路径确认（上一 release 可下载 + normalize 双向兼容）

任一关键项失败 → 保持 pre-release（v0.7.0 先例）。

## 4. 回滚路径（R129-G6：六对象逐一）

| 对象 | 回退方式 | 注意 |
|---|---|---|
| 插件本体 | 导入旧 release package.zip 覆盖 | normalize 双向兼容（新→旧忽略未知字段） |
| 动作包 .qa | Quicker 内删除动作；.qa 文件留档 | 不重放写入（appendBlock 类不会自动补发） |
| 提示词 | promptVersion 记录于快照/文档，按版本回退文本 | — |
| Agent skill | 未发布（planned） | 上线时登记回退方式 |
| MCP server | 无安装态（node 直跑）；回退=切旧 commit 运行 | 独立发版后改用 npm 版本回退 |
| 配置 | bridge-settings.json 手改可逆；normalize 兜底 | — |

**不变量：回滚不重放写入、不删除业务结果**（动作产生的块/打卡记录属于用户数据，与插件生命周期解耦）。

## 5. 外部试用准备（R129-G6，门槛后执行的材料清单）

- 无个人数据测试工作区（新建空工作区脚本化步骤）
- 脱敏动作包（不含 Token/文档 ID——导出自查清单已有）
- 反馈模板（首成功用时/失败点/净节省一行记录——复用 G2 §7 表）
- 退出方式（卸载动作+禁用插件+删除 petal 目录说明）
- 门槛：G2-可发布 + 文档事实表无"E0 假设级"宣传

## 6. 价值指标定义（R129-G6：统一口径，杜绝替代指标）

| 指标 | 定义 | 反例（禁止） |
|---|---|---|
| 闭环率 | 发起→verified 结果 / 发起总数 | 生成字数 |
| 恢复率 | 失败后经恢复路径达成 / 失败总数 | AI 回答条数 |
| 净节省时间 | 手动耗时 − (自动化耗时+修正耗时) | "效率提升 %"（无基线） |
| 信任 | 用户对 AI 结果的采纳率（不修正） | 好评率 |
