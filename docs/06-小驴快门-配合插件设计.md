# 小驴快门（Lv QuickGate）—— 小驴生态中枢与外部动作网关设计

> 定位：**小驴生态中枢 + 外部统一网关**。在思源内部统一发现、调用和编排小驴插件能力；同时让 Quicker、手机快捷指令、脚本等外部程序调用思源「窗口内」能力。核心是公开 capability、命令、上下文、事件和工作流契约，命令面板只是其中一类能力。
> 仓库：`siyuan-quickgate`；品牌顺延小驴系。遵循既有纪律（D-255 / D-0012）：**不读取、不监听其他插件私有存储；只走宿主公开注册表与公开桥**。
> 协议信封、文件治理、多设备约定、验收基线：见 [02-小驴桥协议-v1.1](02-小驴桥协议-v1.md)，本文不重复，只写快门特有内容。

## 1. 为什么需要它（与 02 桥的分工）

| | 快门（本插件） | 各插件自己的桥（02 协议） |
|---|---|---|
| 调用什么 | 公开 capability、插件命令、上下文、事件和工作流 | 插件数据方法（recordEvent / recordInteraction…） |
| 粒度 | 无参或简单参数 | 结构化参数与回执 |
| 接入成本 | 中枢提供统一契约；插件只需公开 manifest/adapter | 每插件单独维护外部桥 |
| 典型用途 | 「发现插件能力」「组合打卡+人脉+闪卡流程」 | 「一键打卡并报连击」「记人脉交集并报人数」 |

### 1.1 面向小驴生态的共性服务

快门的内部能力分为六类，所有小驴插件和外部客户端都可按 capability 协商使用：

| 能力组 | 中枢职责 | 首批消费方 |
|---|---|---|
| `registry.*` | 注册插件 ID、版本、协议版本、能力、就绪状态和健康检查 | 管家、诊断页、超级面板 |
| `commands.*` | 枚举/搜索/执行公开命令，统一确认、审计和超时 | Quicker、管家、雷切工作台 |
| `context.*` | 当前文档、焦点块、选区、工作区和前台场景快照 | 拾遗、管家、Quicker |
| `events.*` | 受限的本地事件发布/订阅，带 schema、来源和幂等键 | 打卡、闪卡、考试、拾遗 |
| `workflow.*` | 编排多个插件的查询/受控写入，逐步确认、失败停止和回执 | 管家、超级面板、Quicker |
| `diagnostics.*` | 版本、能力、桥、配置和最近失败的统一报告 | 所有插件与用户排障 |

建议的注册形状（**待 M0 实证，不视为已存在 API**）：

```ts
registerCapability({
  pluginId: "siyuan-<name>", version: "x.y.z", protocol: 1,
  capabilities: ["context.read", "events.publish"],
  whenReady: () => Promise<boolean>,
  health: () => Promise<{ ok: boolean; message?: string }>,
});
```

七款插件按职责接入：雷切提供工作上下文和受控写，打卡提供记录/汇总，拾遗提供捕获/整理，管家提供聚合与流程入口，闪卡提供到期/制卡/复习，考试提供题库/会话/成绩，未来插件沿同一 manifest 接入。业务 API 名称需以各插件公开契约为准，中枢不得猜测或读取私有存储。

## 2. 架构与通道演进

### 2.1 v1（M1~M2）：前端插件 + NDJSON 桥

- 纯前端插件；栈：`siyuan-note/plugin-sample-vite-svelte` 模板（Vite 8 + Svelte 5 + pnpm，Node ≥24，`main` 分支，仓库名=name）。
- 桥文件 `data/storage/petal/siyuan-quickgate/bridge/{commands,results}.ndjson`，轮询 **500ms**，退避规则以 02 §5 为准（当前设计为封顶 30s；实现前需统一状态机）。
- make-link 软链到 `<SIYUAN_WORKSPACE>\data\plugins\siyuan-quickgate\` 联调（真实路径只保存在本地开发配置）。

### 2.2 v1.5（可选加速）：广播通道，不动内核

内核已内置广播端点族（3.8.x 实存，端点表核实）：

```
外部 Quicker ──POST /api/broadcast/postMessage {channel:"quickgate-cmd", message:<信封JSON>}──► 内核频道
思源前端快门 ──GET(SSE) /es/broadcast/subscribe?channel=quickgate-cmd──► 收到命令 → 执行
回执：快门前端 postMessage 到 "quickgate-res" 频道；Quicker 用 WebSocket 模块常驻 /ws/broadcast 接收
```

- 优点：毫秒级往返，**无需 kernel.js、无需逐插件发版**；NDJSON 作为离线兜底保留。
- 风险/实测项：频道鉴权方式（Token query?）、消息大小上限、SSE 在思源渲染进程的可用性、频道生命周期（谁创建/超时）。
- 决策点：M1 验收后如果 NDJSON 延迟体验不可接受（>1.5s 感知明显），才投入 v1.5。

### 2.3 v2（M3）：内核插件私有路由

`kernel.js`（内核 goja 运行时）注册 `POST /plugin/private/siyuan-quickgate/exec`（自带鉴权+管理员检查），经 broadcast/RPC 中继到前端执行，**同步返回回执**。部署要求与 kernel↔frontend 请求-响应 API 以模板 `docs/kernel-plugin.md` 为准（实现前重读）。NDJSON 信封字段原样平移（02 §9）。

## 4. 命令注册表：读取与执行的安全语义

### 4.1 读取

- 数据源 = **宿主命令面板运行时注册表**（与 Ctrl+P 同源，Plugin API `addCommand` 注册后即在此），不是任何插件私有存储文件。
- **M0 必须先实证**（见 §6 spike ①）：在 3.8.5 控制台定位注册表对象的真实路径；把它封装为唯一访问点 `registry.ts`，结构探测失败 → 降级只暴露快门自身命令 + 提示「宿主版本不兼容」，**永不抛错阻断启动**（小驴自管 JSON 纪律）。
- 缓存：内存缓存 + 失效时机（`pluginsupdated` 类宿主事件若存在则监听，否则 TTL 60s）。

### 4.2 执行

```ts
// 核心语义：等价于用户在命令面板选中该命令
const cmd = findCommand(pluginName, commandId);   // 只在注册表里找
if (!cmd) return reject("命令不存在：可能插件已停用");
if (settings.confirmExec) {
  bringSiYuanToFront();                               // 08-O10：先激活思源，防后台弹窗无人点导致超时拒绝
  const ok = await confirmFor(pluginName, commandId); // 官方 confirm 对话框，30s 超时=拒绝
  if (!ok) return receipt("rejected", "用户未确认");
}
try { await cmd.callback(); receipt("recorded"); }
catch (e) { receipt("failed", `${e?.message ?? e}`); }   // 崩溃兜底，绝不外泄到宿主
```

- 「执行前确认」总开关默认**开**；黑名单插件不暴露。超时回执文案写明「需要确认但思源在后台/未响应」。
- `plugin.api` 高级透传：独立开关默认**关** + 插件允许名单（默认仅已完成契约审计的适配器）；语义化 op（checkin.*/contacts.*）不受此开关限制，但受桥总开关管（08-O17）。新插件必须先完成公开契约和能力协商，不能因进入生态名单自动开放透传。
- 审计：`audit.json`（快门自管 JSON，schemaVersion 1）最近 200 条 `{time, plugin, command, status, elapsedMs}`，设置页可查看/清空/复制。

## 5. 数据结构与设置

### 5.1 核心类型（`src/types/bridge.ts`）

```ts
interface BridgeCommand { v: 1; id: string; op: string; args: Record<string, unknown>;
  createdAt: string; ttlMs?: number; reply?: boolean; device?: string; }
interface BridgeReceipt { v: 1; id: string; op: string;
  status: "recorded"|"duplicate"|"rejected"|"failed"|"unsupported"|"expired";
  data: unknown; message: string; finishedAt: string; plugin: string; elapsedMs: number; }
interface PluginCommandInfo { id: string; title: string; accelerator?: string; }
interface AuditEntry { time: string; plugin: string; command: string; status: string; elapsedMs: number; }
```

### 5.2 自管设置 `bridge-settings.json`（schemaVersion 1，normalize 纪律同打卡/人脉）


## 10. 验收用例（快门特有，02 §8 之外）

1. `commands.list` 结果与命令面板（Ctrl+P）可见条目一致（同一时刻人工比对）。
2. `commands.run` 执行一个「有副作用的命令」（如雷切打开切换器）→ 效果出现；确认开关开时先弹确认。
3. 确认框 30s 不点 → 回执 `rejected`，命令未执行。
4. 停用某插件后再 `commands.run` 其命令 → `rejected`「命令不存在：可能插件已停用」。
5. 桥关闭期间积压的命令，重开后过 TTL 的全部回 `expired` 且不执行。
6. 卸载快门 → bridge 目录随 petal 删除，思源无残留报错。
