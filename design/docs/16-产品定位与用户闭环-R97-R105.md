# 产品定位与用户闭环调研 R97~R105：从命令网关到意图结果中枢

> 调研日期：2026-10-02。开始时 TODO 共 750 项（完成 192、未完成 558）；本轮只扩充定位研究和候选待办，不开发、不部署、不配置真实自动化。
> 本轮使用第一性原理重新审视项目：用户不是为了调用 HTTP、MCP 或某个插件而使用快门，而是希望在信息和能力分散时，少切换、少重复、少遗忘，并得到可确认、可回溯、可继续使用的结果。候选待办登记在 [TODO §15](../TODO.md)。

## 1. 定位重述：用户购买的是结果连续性

### 1.1 用户最终要完成的事

快门的核心问题可以写成：**用户已经产生一个意图，但完成意图所需的上下文、资料、业务能力和回执分散在不同应用和小驴插件中。** 快门负责把意图变成一条用户看得懂的结果链：

`意图 → 识别上下文 → 选择能力 → 预览影响 → 用户确认 → 受控执行 → 结果回执 → 后续行动/复用`

这比“统一外部入口”更具体，也比“做一个全能自动化平台”更可控。快门的价值不在保存另一份业务数据，而在减少跨应用协调成本、降低错误写入和未知状态，并让一次操作能够成为下一次行动的可靠输入。

### 1.2 一句话定位候选

> **小驴快门：把用户在任意入口提出的意图，安全地变成小驴生态中可解释、可确认、可追踪、可复用的结果。**

外部网关、生态中枢、超级面板、工作流和 MCP 都是实现形态；用户界面应优先展示“我要完成什么”和“结果发生了什么”，再按需要展开协议、插件和技术细节。

### 1.3 不属于快门的事

快门不成为第二套笔记库、第二套任务/日历/学习调度系统、通用备份清理器或自建模型服务。业务事实由对应插件/思源 owner 保存；快门负责发现、组合、授权、执行、回执和跨模块的最小引用。

## 2. 外部产品机制与可借鉴边界

PowerToys Command Palette 将启动应用、命令、文件和系统工具放在一个可扩展、键盘优先的入口；Alfred 把工作流作为可组合对象，让用户替换重复的手工步骤；Todoist 的快速添加把自然语言日期解析作为输入辅助；Notion 的按钮把重复动作收在页面上下文中；Obsidian Bases 把结构化视图建立在已有属性上。[PowerToys Command Palette](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/overview)、[Alfred Workflows](https://www.alfredapp.com/help/workflows/)、[Todoist 自然语言快速添加](https://todoist.com/help/articles/quick-add-using-natural-language-recognition-Q5VpxV)、[Notion Buttons](https://www.notion.com/help/buttons)、[Obsidian Bases](https://help.obsidian.md/bases)。

这些产品分别解决入口、组合、输入解析、上下文动作和结构化视图；本项目应借鉴用户心智模型和验收方式，不能把它们的完整产品范围直接复制到快门。快门的差异化应集中在小驴插件公开能力之间的责任边界、确认与回执、跨入口一致性和结果继续使用。

## 3. 用户闭环与核心状态

任何核心场景都应能回答七个问题：我想完成什么？快门理解了什么？它将读取/写入哪里？我确认了哪一版？现在进行到哪一步？结果是否真的发生？下一步能否继续？建议统一状态：`draft → understood → previewed → confirmed → running → completed/partial/unknown → reconciled → reused/archived`。状态不是 UI 装饰，而是用户在网络、插件或窗口中断时恢复信任的依据。

## 4. 待验证的产品判断

1. 首次价值应是“一个自然入口完成一个完整结果”，而不是展示最多能力。
2. 高频价值应是“结果能再次被找到、引用和继续执行”，而不是单次响应更快。
3. 深度价值应是“跨插件组合仍尊重各自 owner”，而不是把所有数据复制进中枢。
4. 智能化应先减少选择和解释成本，再考虑自动触发；任何高影响写入都保留用户可理解的确认点。
5. 采用度量应看任务闭环率、恢复成功率、二次利用率和净节省时间，不能只看调用次数。

## 5. 研究证据门槛

R97~R105 的候选都需要区分：用户明确表达的问题；外部产品已经证明的交互机制；结合当前契约提出的设计假设；尚缺 owner、用户样本或真机验证的未知项。每一项正式排期前要有用户任务、替代做法、输入/输出样例、正常/中断/未知/撤销路径、权限和长期维护成本。
