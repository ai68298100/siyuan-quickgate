# 生态调研 R9 · 数据备份/导出范式（喂 G5 数据主权线）

> 循环 C 第 9 轮（2026-10-06）。对象：Obsidian 数据导出插件、uTools 备份、Raycast 设置同步、1Password 导出。
> 背景：R302 已交付结果中心 CSV/JSON 导出；快门用户数据（settings/favorites/audit/results）全在 petal
> 存储并随思源云同步——备份语义部分覆盖，缺的是"一键全量导出/导入"。

## 1. 各家机制速览

| 产品 | 核心机制 | 对快门可借鉴点 |
|---|---|---|
| Obsidian Dataexport/备份插件 | 单 JSON 全量导出（设置+数据），导入时 schema 校验+可选合并 | 一键 JSON 全量（设置+收藏+审计+回执）+导入 schema 校验 |
| uTools | 备份文件带版本号；导入时降版本走迁移链 | 导出带 schemaVersion，导入走既有 normalize* 迁移链（已有基础设施） |
| Raycast | 设置随 iCloud 同步；导出仅开发用途 | 云同步已由思源覆盖——不重复造 |
| 1Password | 导出默认提醒敏感 + 明确格式警示 | 导出时敏感提示（审计含 op 名不含参数——风险低但仍提示） |

## 2. 交叉结论（数据主权线排序）

1. **一键 JSON 全量导出**是各家共同点；快门四载体（settings/favorites/audit/results）+ processed 台账
   均为 JSON/NDJSON，拼装零转换成本——技术可行性高。
2. **导入**必须走 normalize* 校验链（schemaVersion 迁移），拒绝/合并策略需明确（跳过 vs 覆盖）。
3. **云同步已覆盖日常备份**——一键导出的定位是"迁移到新机器/存档"，不是日常备份。

## 3. 立项建议（本轮登记 1 条）

- **R9-A【评估→G5】一键全量导出/导入**：设置页按钮 → 四载体+processed 拼装 JSON 下载；导入走
  normalize* 校验+用户确认覆盖。验收=导出→清空→导入→功能全绿（test: 冒烟 4 载体）。
