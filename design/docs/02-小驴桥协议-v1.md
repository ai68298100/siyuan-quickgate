# 小驴外部命令桥协议（Lv External Bridge）v1.1（主路径定位修订 v1.2）

> 目的：让**进程外程序**（Quicker、手机快捷指令、脚本、HA 等）安全调用小驴打卡 / 小驴人脉 / 小驴雷切 / 小驴快门的窗口内能力。
> 设计原则：**不新造任何写路径**——全部转发给插件已有的窗口内桥方法（`window.siyuanCheckin` v5、`window.LvContacts` v1、雷切 Agent 受控写、快门命令注册表），自动继承其幂等、校验与安全边界。
> 传输：思源内核文件 API（`putFile`/`getFile`），零新依赖。
> **主路径定位修订（08 评审 O1，非线协议升级）**：数据类操作的主路径改为**小驴快门的数据透传 op**（快门在窗口内直接转发到各插件已有公开桥，逐插件免接入）。本协议降级为：①未装快门时的直连兜底 ②手机快捷指令经内核直发的通道 ③协议参考实现。已发布桥的插件无需撤销，两路并存。
> **v1.1 变更**：新增 `ttlMs`/`reply`/`device` 信封字段、`expired` 状态、`bridge.ping` 协商、结果文件滚动上限、多设备行为约定、威胁模型、Quicker 子程序逐步规范。

## 0. 总览与延迟预算

```
Quicker 动作                          小驴插件（渲染进程）
   │ 1. putFile commands.ndjson            │ 每 pollMs getFile（仅思源运行时）
   │    (Bearer 思源Token)                 ▼
   │                                   2. 逐行解析 → TTL 检查 → 能力检查
   │                                   3. 调用已有桥方法
   │ 4. getFile results.ndjson         5. 追加回执（滚动上限 200 行）+ 按已处理 id 惰性压缩
   ▼                                        │
  notify/后续步骤 ◄─────────────────────────┘
```

| 轮询间隔（插件侧） | 命令发出→收到回执 p50 | p95（跨过整轮） |
|---|---|---|
| 500ms（快门推荐） | ~750ms | ~1.0s |
| 3s（普通插件默认） | ~4.5s | ~6s |
| 300ms（动作发起后插件临时加速，可选优化） | ~450ms | ~600ms |

普通插件 3s 轮询即可覆盖数据类动作（打卡/记互动本来就要几秒确认）；快门因承载菜单命令用 500ms。

## 1. 文件布局与治理

```
data/storage/petal/<plugin>/bridge/
  commands.ndjson    # 外部 → 插件；消费者按「已处理 id 台账」做惰性压缩（并发追加不丢失，见 §1.2）
  results.ndjson     # 插件 → 外部；滚动窗口，最多保留最近 200 行
  events.ndjson      # 公开宿主事件流（v0.4.x 起，各来源插件目录；快门代打卡物化）——append-only，
                     # 删除以独立标记行表达（幂等键=原事件键+`:deleted`），消费方按键配对；
                     # 裁剪/合并时必须保留删除标记直至对应原行一并滚出（契约见 quickgate events-workflow-draft）
```

- `<plugin>` ∈ `siyuan-checkin` / `siyuan-contacts` / `siyuan-speed-switch` / `siyuan-quickgate`
- 格式：NDJSON（每行一个 JSON 对象，UTF-8 **无 BOM**，`\n` 分隔）。空行、行尾多余空白必须容忍。
- putFile 参数为工作空间相对路径：`/storage/petal/<plugin>/bridge/commands.ndjson`。
- **文件不存在 = 无命令**（getFile 返回 404/空）。调用方 putFile 直接创建，插件不预创建（避免弄脏同步）。
- 上限：单命令 `args` ≤ 32KB（对齐 Quicker /api/exec）；单文件 ≤ 50 行 / 256KB，超限插件只处理前 50 行。
- **并发写与队列正确性（✅ 已解决，D-0002 算法）**：putFile 是「整文件覆盖写」，追加 = 读旧内容+拼接。曾评估的"消费后覆盖剩余行"存在丢失窗口（插件消费 A 期间外部追加 B 会被截掉）。**现行算法（quickgate 已实现并有 tick 级测试）**：消费者持久化「已处理 id 台账」（bridge-state.json，500 LRU）；压缩时**仅移除台账中的 id 行**，未处理行（含压缩窗口期新追加的行）原样保留；外部并发写回造成的"行复活"按 id 跳过并再次压缩。不存在丢失窗口：任何外部写回都包含其读到的全部未处理行。多外部调用者互覆问题仍存在——约定单写者（Quicker 动作内天然串行）。

## 2. 命令信封（外部 → 插件）

```jsonc
{
  "v": 1,                            // 协议版本，破坏性变更才升
  "id": "qk-20261001-153000-7f3a",   // 幂等键，调用方生成；重复投递回 duplicate
  "op": "recordInteraction",         // 白名单 op，见 §4
  "args": { },                       // 各 op 自有参数
  "createdAt": "2026-10-01T15:30:00+08:00",
  "ttlMs": 60000,                    // v1.1：过期时间；缺省 60s，过期命令回 expired 不执行
  "reply": true,                     // v1.1：缺省 true；false = 只执行不写回执（fire-and-forget）
  "device": ""                       // v1.1：可选目标设备名（见 §1.1 多设备）；空 = 任一设备
}
```

约束：`id` ≤64 字符 `[A-Za-z0-9_\-]`；`args` ≤32KB；建议 `id` 形如 `qk-<yyyyMMdd-HHmmss>-<4位随机>`。

### 1.1 多设备行为（petal 目录随思源同步走——必须正视）

`data/storage/petal/` 会经思源同步复制到其他设备，因此 commands.ndjson 可能出现在多台同时开着的思源里。约定：

- **v1 诚实边界**：不承诺「多设备同开时命令只在某台执行」。文档与设置页明示：发命令时最好只开一台思源；多开时命令可能被任一设备消费（数据都进同一个同步空间，不丢，只是执行位置不确定）。
- **可选优化（v1.1，各插件自愿）**：插件在非 petal 的本地目录（`data/storage/local/`，不随同步）记录 device 名；信封 `device` 非空且不匹配时**跳过不消费**（不截断文件，留给目标设备）。

## 3. 回执信封（插件 → 外部）

```jsonc
{
  "v": 1,
  "id": "qk-20261001-153000-7f3a",
  "op": "recordInteraction",
  "status": "recorded",   // recorded | duplicate | rejected | failed | unsupported | expired
  "data": { "recorded": 3 },
  "message": "已为 3 人记录交集",   // 中文，可直接展示
  "finishedAt": "2026-10-01T15:30:01+08:00",
  "plugin": "siyuan-contacts",     // v1.1：来源插件（一个 results 文件只会有一个插件，冗余便于排查）
  "elapsedMs": 412                 // v1.1：执行耗时（诊断用）
}
```

- `expired`：`createdAt+ttlMs` 已过（调用方早放弃了）——仍回执便于审计。
- `unsupported`：op 不在白名单，或能力被停用（桥开关/雷切受控总开关）。
- `rejected`：参数非法/被既有桥校验拒绝（沿用各桥中文报错）。
- `failed`：执行抛异常（中文 message，含异常名）。
- **results 治理**：每次追加后裁剪到最近 200 行；外部取走后**不删除**（幂等查询靠按 `id` 过滤），避免外部忘记清理导致文件膨胀。

## 5. 插件侧实现规范

```
轮询循环（Web Lock 临界区 "lv-bridge:<plugin>"）:
  1. enabled? 否 → sleep(pollMs×退避) continue
  2. getFile commands.ndjson
     ├ 404/空 → sleep(pollMs) continue
     └ 有内容 → 逐行:
         a. JSON.parse 失败 → 回执 rejected("命令行不是合法 JSON")
         b. id 已在去重缓存(最近200) → 回执 duplicate，跳过
         c. createdAt+ttlMs < now → 回执 expired，跳过
         d. device 非空且≠本机 → 跳过（不回执不截断）
         e. op 白名单校验 → unsupported
         f. try 调用桥方法 → recorded / failed（catch: message=中文+异常名）
     3. 若 `reply` 不为 false，putFile results.ndjson = 旧内容追加新回执，裁剪至 200 行（写后回读验证，两次不收敛即告警）；`reply:false` 的任何状态都不写回执
     4. 按已通过原子认领/锁定的队列方案确认消费，不得用旧快照裸覆盖 commands.ndjson
     5. 去重状态写入可跨重启恢复的存储；仅保留最近 200 条时必须明确超窗重放边界
  退避：连续 3 次 getFile 异常 → 间隔×2，封顶 30s；成功后复位
```

- 轮询必须单飞：`while (!closed) { await pollOnce(); await sleep(nextDelay); }`，不能用慢任务期间会重入的 `setInterval`；Web Lock 只负责多窗口，不替代生产者/消费者队列锁。
- `bridgeEnabled` 关闭时不消费（命令积压，重开后按 TTL 过期一批是预期行为）。
- 插件 onload 后延迟 3s 启动轮询（避开启动高峰）；onunload 清理定时器。
- 桥目录与文件不进插件的 schemaVersion 自管 JSON 体系（它们是通信信道不是配置）。

## 6. Quicker 侧子程序规范

### `SY·内核请求`（所有内核调用的唯一入口）

| 步骤 | 模块 | 说明 |
|---|---|---|
| 1 | 状态检查 | statestorage 读 `sy_url/sy_token`；没有则读 `%APPDATA%\siyuan\env` 解析后写入 |
| 2 | HTTP 请求 | `{sy_url}{端点}`，Header `Authorization: Token {sy_token}`，JSON 体，超时 10s |
| 3 | 失败分支 | 按 04 §8 通用错误分支表处理（401→令牌引导；超时→「思源未运行？」） |
| 4 | 输出 | 状态码 + 文本结果；调用方自行 jsonextract |

> **内核路由快路径（spike⑩ 通过后启用）**：op ∈ KERNEL_OPS（bridge.ping / registry.list / diagnostics.report / events.list·pull / config.discover / template.new，见 quickgate `src/ops.ts`）时改走 `POST {sy_url}/plugin/private/siyuan-quickgate/exec` 同步直呼（信封同形，响应在 `data` 里即回执，详见 quickgate docs/api.md 双通道路由表）；任何失败（404/超时/非 0）回退本子程序常规路径。`lv-cli.mjs exec` / `Send-LvCommand.ps1 -Exec` 即此通道的参考实现。

### `LV·发命令`（putFile 追加一行）

1. 入参：插件名 / op / args（文本） / 可选 ttl
2. 生成 id：`qk-{yyyyMMdd-HHmmss}-{4位随机}`；createdAt=现在。信封可选字段（按需携带）：`ttlMs`（过期不消费）、`device`（目标设备名，多设备定向）、`reply:false`（不写回执，fire-and-forget）——字段语义见 §2
3. `getFile` 旧 commands（404 视为空）
4. C# 拼 NDJSON 新文件 = 旧文本（去尾部空行）+ `\n` + 新行（对象 `JsonConvert.SerializeObject`，注意 `\n` 转义）
5. 写临时文件 → HTTP `putFile`（**Multipart 表单**：`path` 文本字段 + `file=FILE:{临时文件路径}`）
6. 输出 id 供 `LV·取回执` 用

### `LV·取回执`

1. 入参：插件名 / id / 最大等待（默认 8s）
2. 循环 ≤ 10 次：HTTP `getFile` results.ndjson（404 视为空）→ 按行 JSON.parse，匹配字段 `id`，不得依赖空格或字段顺序 → 返回该对象
3. 命中 → 返回 status/message/data；未命中且超时 → 返回 `timeout`（动作再决定 notify 文案）
4. 逐行解析 JSON；坏行跳过并记录诊断，不能用 `Contains` 匹配

> 等待上限按 op 区分：普通无确认命令约 1.2s，数据类操作约 8s；`commands.run` 可能触发 30s 确认窗口，应等待约 35s 或先返回 `pending` 后按原 id 查询。超时不得自动换新 id 重试。

## 7. 威胁模型与安全边界

| 威胁 | 评估 | 缓解 |
|---|---|---|
| 恶意 Quicker 动作（从动作库装）发命令 | 与它直接调内核 API 的破坏力相同（同持 Token 才能写桥文件） | 无新增面；动作库分享注意清 Token（见 03 附录） |
| 本机其他用户/程序写桥文件 | 需要工作空间文件写权限 ≈ 已持有 Token | 不引入新面 |
| 命令注入（args 带怪内容） | 各桥已有参数校验 + op 白名单 | 信封字段长度/类型校验；自由文本只进桥方法不进 SQL |
| 桥文件被同步放大（历史版本堆积） | 思源文件历史保留 | results 滚动 200 行 + commands 消费即截断，文件常态 <100KB |
| 命令重放 | 同 id 回 duplicate | ttlMs 过期兜底 |
| 伪装来源 | 桥天然只有「quicker」一个来源，记入审计 | 打卡侧 source 固定；快门记审计日志 |

- 插件**永不**执行命令中的代码，只接受白名单 op 与有界参数。
- 桥文件通道不做鉴权——鉴权等价于内核 Token（能写文件者已能调任意内核 API）。

## 8. 验收用例（每插件）

1. 正常链路：发 1 条命令 → pollMs+ε 内 results 出现 `recorded`，思源 UI 数据可见。
2. 幂等：同 id 重发 → `duplicate`，数据不重复。
3. TTL：发一条 `ttlMs=1` 的命令，插件轮询周期设长 → 回执 `expired` 且不执行。
4. reply:false → 执行生效、results 无新行。
5. 非法输入：未知 op → `unsupported`；超长 note → `rejected`；坏 JSON 行 → `rejected` 且不影响下一行。
6. 开关：关→积压；开→顺序消费，过 TTL 的报 expired。
7. 思源重启：轮询自愈；`whenReady` 未就绪期间命令留队，就绪后处理。
8. 边界：51 行命令只消费前 50 行且余行保留；args >32KB（32768 字节）整行 rejected。
9. 多窗口：两个思源窗口同开，同一命令只执行一次（Web Lock）。
10. `bridge.ping`：返回 protocol/plugin/version/pollMs，Quicker 据此点亮菜单。

## 9. v2 平移说明（NDJSON → 同步通道）

**现状（v0.5.0+）：内核私有路由已实现**——`POST /plugin/private/siyuan-quickgate/exec`（实验性）同步处理内核可处理的 op 子集（bridge.ping / registry.list / diagnostics.report / events.list·pull / config.discover / template.new，见 `src/ops.ts` KERNEL_OPS）；前端专属 op 回结构化 `unsupported` 指引回本通道。spike⑩ 校准通过后，「内核子集走同步直呼 + 其余走 NDJSON」成为双通道常态，NDJSON **不退役**（承载全部前端 op）。

**已实现（v0.6.0，spike⑤ 真机实证后落地）：v1.5 广播快路径**——外部客户端 `POST /api/broadcast/postMessage {channel:"qg-cmd", message:<信封JSON>}` 推命令（Token 鉴权），快门前端 SSE 订阅 `/es/broadcast/subscribe?channel=qg-cmd` **到达即执行（毫秒级）**，回执仍写 results.ndjson。与 NDJSON 慢路径共用幂等台账（**预留语义**：同步 check+mark 后才 await，双通道竞态只执行一次）；`broadcastEnabled` 独立开关**默认关**（新外部面红线）；断流指数退避重连。三客户端就绪：`lv-cli.mjs fast` / `Send-LvCommand.ps1 -Fast` / e2e 内置延迟测量。

剩余未实现的 v2 候选：前端中继（D-0010 暂缓）。平移时：

- 信封（§2/§3）字段**原样保留**，只是传输从「文件+轮询」换成「一次 HTTP/WS 往返」。
- Quicker 侧只改 `LV·发命令`/`LV·取回执`/`SY·路由` 内部实现（对外入参/出参不变），所有动作零改动。
- 调试工具已就绪：`lv-cli.mjs exec` / `Send-LvCommand.ps1 -Exec` 直呼内核路由；`lv-cli.mjs fast` / `-Fast` 走广播快路径。

## 10. 三通道信封差异与幂等台账口径（L636·R226 源码核对定稿）

> 结论先行：**「回执形状」三通道同形（§3，result-contract §2.1 成立）；「幂等台账」不共享**——内核路由无调用方 id、不进 processed 台账。补齐 id/externalRef 之前，任何文档不得宣称「三通道共享完整幂等台账」。

| 通道 | 命令 id 来源 | 回执载体 | processed 台账 | 跨通道/重放去重 |
|---|---|---|---|---|
| NDJSON 桥 | 调用方生成（信封必带，§2） | results.ndjson 同 id 行 | ✅ check+mark（LRU=auditMax） | ✅ duplicate 可判 |
| 广播 v1.5 | 调用方生成（postMessage 信封） | results.ndjson 同 id 行 | ✅ 与 NDJSON 共用 | ✅ duplicate 可判 |
| 内核路由 | **无调用方 id**（请求体仅 `{op,args}`）；回执 id 恒 `kernel` | HTTP 响应即回执（`data.data` 包裹），**不写 results.ndjson** | ✗ 不进台账 | ✗ 仅同步 HTTP 语义天然一次；超时重试/跨通道重放会重复执行 |
| MCP | JSON-RPC id 独立；慢/快路径的桥命令 id 由客户端 `mcp-<日期>-<随机>` 生成；直呼内核路由时同内核行 | tools/call 投影 | 经 NDJSON/广播 ✅；直呼内核 ✗ | 混合（随所用路径） |

由此派生的使用纪律：

1. **写副作用 op 走内核路由须谨慎**：`template.new` 在 KERNEL_OPS 内，网络超时后的「盲目重试」会创建两份文档——重试前先查目标文档是否已生成（safety-gate §6 差距②/L627 收口跟踪中）。
2. 幂等敏感调用（`checkin.record` 等）始终走 NDJSON/广播通道：externalRef=命令 id 的幂等键只在有台账的通道成立。
3. 内核路由的适用定位维持「只读探测 + 实验性写」：bridge.ping / registry.list / diagnostics.report / events.list·pull / config.discover 是安全面；`template.new` 依赖 safety-gate §7 路径守卫落地。
4. 若 v2 给内核路由补 id：请求体加 `id`（调用方生成）且回执透传，processed 台账按同规则记账——信封仍只做**追加**，不破坏 §2/§3 兼容。
