## 1. 先给结论

小驴快门的工程底座已经达到“可交付的本地优先网关”水平：统一信封、幂等、NDJSON 桥、内核同步路由、SSE 广播、命令注册表、生态 manifest、事件流、工作流、审计、收藏/最近使用、MCP 只读/写门控和内置 Agent 能力均已进入实现或发布链。

产品层仍处在“可靠后台 + 设置/诊断入口”阶段。设计中的任务首页、统一命令面板、意图/计划/结果/恢复中心、AI 工作台和 Quicker 作者工作台尚未接入当前安装包。下一阶段应收敛到一条可观察、可恢复、可复用的纵向用户闭环，再复制到更多插件场景；继续增加大量新 op 或扩展原型页面，会扩大维护面而不能直接提高用户成功率。

推荐的首条纵向闭环是：**外部选区/文本 → 目标与影响预览 → 用户确认 → 写入收件箱/今日日记 → 业务回执 → 查询、打开原文或安全恢复**。这条链能同时验证能力发现、权限、幂等、三通道、结果未知、移动/桌面入口和文档表达。

## 3. 产品判断与范围纪律

### 3.1 产品定位

对用户的短定位建议统一为：

> 小驴快门是思源笔记的本地优先生态网关：把 Quicker、CLI、快捷指令、MCP/AI 与小驴插件的意图，经过能力发现、权限确认、幂等执行、业务回执和失败恢复，变成可核验结果。桥、广播和 `plugin.api` 默认关闭，业务数据仍归各自插件所有。

### 3.2 三个产品层次

1. **MVP-1：可靠入口与可观察性**：首跑向导、健康状态、能力目录、命令入口、回执/未知状态、诊断和安全恢复。
2. **MVP-2：一条任务闭环**：快速捕获、影响预览、确认、执行、业务回执、原文回链和恢复操作。
3. **MVP-3：扩展层**：AI 只读研究、ActionSpec 草稿、工作流模板、Quicker 作者链、跨设备续接和更多生态适配器。

在 MVP-1/2 验收完成前，冻结新增大范围业务 op、复杂超级面板和模型接入；新需求必须说明它服务哪条用户闭环、拥有者、失败恢复和停止条件。

验收：制造断线、超时、重复、迟到、双窗口和坏行后，系统不会重复写入、不会把 unknown 改成失败/成功，并能导出最小诊断。

### G3 · 命令入口与快速捕获（P0/P1）

## 6. 产品指标与停止条件

首个纵向样板不以 ping 次数、HTTP 200、AI 回复字数或调用量作为成功标准，至少记录：

- 首次成功时间（从安装到第一条可核验业务结果）；
- 完成率、失败恢复率、unknown 安全处理率；
- 重试造成的重复写入数（目标为 0）；
- 用户从结果回到原文/业务插件的成功率；
- 二次复用率、平均等待时间和主要失败阶段；
- Android/桌面/外部 host 各自的完成率与误触发率。

若一条能力无法说明业务 owner、写入目标、幂等键、失败出口和验证证据，则停留在设计态，不进入默认菜单或宣传页。
