## 1. 核心发现：本地速记已被内核自动消费（L333 目录监听方案否决）

    ...  // 读取→转为文档→移入目标笔记本（boxID），带 syncLock 与保存笔记本可用性校验

- 移动端速记 **3.7.0 已落地**（[知乎官方介绍](https://zhuanlan.zhihu.com/p/2054722589784856150)：长按图标闪念速记 + 跨应用分享；[issue #14294](https://github.com/siyuan-note/siyuan/issues/14294) 记录了架构约束：必须内核进程运行才能落盘）。
- 本地速记文件（`util.ShortcutsPath/shorthands/`）由内核 **MoveLocalShorthands 自动消费**：转文档→移入用户配置的「速记保存笔记本」。
- **推论**：L333 的「快门监听该目录→物化」与内核自身消费者**竞争同一目录**（文件会被内核移走；时序不确定）→ 方案否决。
- **改道**：速记消费终点=普通文档（进入用户笔记本）——既有 SQL/events 面天然可见，**无需新数据源**；速记→文档后的一切集成走既有路径。

## 5. 追加：思源 3.8 内置 CLI 能力面详查（R238）

`kernel/cli/cmd/` 枚举（gh 源码直读）：**24 个命令域**——asset / attr / block / bookmark / dailynote / database / document / export / file / history / import / inbox / notebook / outline / ref / repo / search / sql / sync / system / tag / template / workspace（cobra 架构，`sql` 支持 `--limit`、表格式输出）。

**边界对照**：内置 CLI = **本机单用户的内核操作面**（直连内核/数据目录，覆盖 SQL 查询、日记、搜索、同步、仓库管理等）；快门 = **跨宿主网关 + 生态编排**（Quicker/快捷指令/CLI/MCP 多宿主共用一条契约，加命令注册表/模板/工作流/收藏）。

**结论**：①本机脚本场景用户可直接用内置 CLI（快门 lv-cli 的「本机便利」价值被部分覆盖——诚实记录）；②快门差异化守住跨宿主与生态层，与 R234 调研的 selective-loading 结论一致（不追平内核 CLI 的 24 域，那不是快门的问题域）；③L561 对比矩阵增「思源内置 CLI」行（随下次触碰落地）。
