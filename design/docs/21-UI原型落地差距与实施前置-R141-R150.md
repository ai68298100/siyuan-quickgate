# UI 原型落地差距与实施前置 R141~R150

> 研究日期：2026-10-02。对照 [UI 原型](20-体验页面与内容深化调研-R131-R140.md)、完整 [TODO](../TODO.md) 与快门 v0.7.1 实现快照 `1409256c4c3c05710633d4d000e526c56f6e30ae`，核对页面能否由真实数据与公开能力支撑。本轮只研究、校正原型和登记待办，不开发、不接入真实模型、不导出真实动作、不改运行配置。新增 60 项登记在 TODO §20，另细化 16 个原有父项，不重复计数。

## 1. 核心判断

达到原型效果需要的不只是页面组件。首页数字需要可靠的任务查询投影；步骤条需要可观测事件；确认按钮需要真正的服务授权；结果卡需要 owner 证据；恢复按钮需要公开恢复能力。先证明数据和行为，再评审视觉，才能使“可确认、可回查、可恢复”成为用户实际得到的结果。

本轮把工作分成三类：新增且有独立产物的实现前置、原有父项的具体验收、必须修正的原型假设。C1~C8 的状态、权限、上下文和回执仍只维护一份规范，页面只消费和呈现它们。

## 4. 页面事实模型的约束

原型状态词是展示词汇，不是一条从 draft 到 verified 再到 archived 的单一路径。应在 C1 下至少分别表达：

| 维度 | 示例 | 不允许的推断 |
|---|---|---|
| 任务阶段 | 草稿、待确认、执行中、执行已结束 | 生成计划不能算业务完成 |
| 执行事实 | 未执行、已提交、部分执行、拒绝、失败、未知 | unknown 不能被 timeout 文案改成已失败 |
| 证据核验 | 无证据、待核验、owner 已核验、人工核对、证据失效 | recorded、HTTP 200 或截图不能自动成为 owner verified |
| 用户处理 | 待跟进、已查看、已决定放弃、已归档 | 放弃/已读/归档不能改写业务执行事实 |

允许同一任务同时是“执行已结束、部分执行、其中一项结果未知、需用户处理”。UI 使用统一映射与优先级显示主状态，详情保留每个维度。最终字段名以 C1 合同为准，不能把这张分析表再做成一套平行协议。

首页“今日完成”按逻辑任务和用户所选时区计数；一个意图的多个子步骤、重试和修订不成为多个新任务。网络不可达、历史被裁剪或入口未接入观测，都必须显示覆盖范围和截至时间，不能转成零条任务。

草稿恢复、任务查询和持久化执行授权必须分开。沿用当前短期内存计划决策时，重启只能恢复输入和可读摘要；继续任务必须重新检查目标、权限和能力并生成新计划。

## 5. 原型需要同时修正的假设

| 原展示 | 修订方向 |
|---|---|
| “拾遗可用、正在调用、已返回回执” | 明示设计样例和未定位；首个真实捕获场景选已验证能力，owner 随能力发现显示 |
| “预计小于 2 秒” | 有测量基线才展示估算；否则写尚未测量，不把目标 SLO 当实测 |
| “创建记录不可逆” | 依据 owner 的撤销/补偿合同说明影响，无法判断就说明未声明 |
| “取消任务、提交前都可取消” | 区分停止观察、请求停止、阻止后续与不可取消副作用；无公开接口不能承诺取消 |
| 四个统一恢复出口全部可点击 | 四类是候选路径，逐项检查能力、权限和原身份，不支持时解释人工路径 |
| “仅保存计划” | 写为保存计划草稿；不保留旧授权，不延长现有五分钟计划有效期 |
| 局部编辑只让受影响确认失效 | 以 Confirmation 合同决定；当前整份一次性确认应重新生成计划并整体确认 |
| 固定五栏导航与固定右侧任务条 | 是信息层级，不是固定几何布局；按 Tab/Dock/Dialog/移动页折叠映射 |
| 展示模型“思考内容” | 只呈现公开处理摘要、工具事件和输出；不假设内部思考可以读取 |
| MCP/外部入口都要求启桥 | 按执行位置和通道解释；已有 kernel-sync 只读路径可在外部桥关闭时工作 |

这不是降低产品目标，而是给每项界面承诺绑定实际条件；只有条件被验证后，按钮和状态才能升级成真实能力。

## 7. 第一批执行顺序和进入条件

1. **G0 事实账本**：对原型字段和操作建来源表，修正样例、版本与状态承诺，标出 R69 等已有阻断。
2. **G1 契约和前置**：先统一 C1~C4、旧回执投影、待核验记录保留、可用操作/确认终结；确定通道和 owner 核验能力。
3. **G2 一个宿主内捕获闭环**：只选择一个输入和一个可验证目标，实现入口、计划、确认、结果、unknown 恢复与最小读模型；AI 仍可帮助起草和解释，但不扩大权限。
4. **G3/G4 AI**：先只读/草稿的上下文、模板和引用；host 能力真实接入并可确认后才做低风险写入。
5. **G5 Quicker 作者链**：核对最低版本、交接方式、暂存包和试运行证据；没有公开自动接口就保留手动交接。
6. **G6/G7 扩展**：再评估跨设备、自动化、多媒体、长期运营和集市；五栏导航可以先保留只读介绍/设计态，不一次实现全部工作台。

MVP-1/2/3 是原型覆盖层级；G0~G7 是实施门禁，两者不直接等同。Quicker 作者链以 [路线 §3](19-待办融合与路线重排-R123-R130.md) 的 G5 为准，历史 G4 等标签保留追溯，不能当成无依赖的立即开发命令。

每张执行卡还需选定唯一 owner、输入/输出、所读/所写/外发、依赖、兼容矩阵、正常/失败/未知/取消出口和回滚证据。UI 模块负责展示与交互，快门服务负责权限、身份和回执，业务 owner 负责实际事实，Quicker/host 负责各自公开生命周期。

## 8. 原型效果的验证方式

把固定时钟、脱敏数据、延迟、模型输出、能力缺席、失效确认、坏行和迟到回执做成可重现状态脚本。先用只读或隔离模拟；之后的真实业务验收必须由 owner 合同支持。

| 路径 | 要观察的实际效果 | 失败/竞态样例 |
|---|---|---|
| 捕获到明确目标 | 预览的范围和目标与实际业务实体一致，能打开原对象，只写一次 | 重复确认、切工作区、目标删除、超时后迟到、无核验证据 |
| AI 只读研究/草稿 | 实际发送范围与所选胶囊一致，引用能定位，接受只生成新计划 | 删除胶囊、旧响应到达、用户编辑被覆盖、模型不可用、无公开轨迹 |
| Quicker 动作草稿 | 规格和动作制品有类型区别，暂存/保存/运行/核验分开 | 版本不足、没有自动交接接口、同名暂存、不可逆真实试运行 |

截图基线绑定实际加载入口、宿主版本、容器尺寸、主题、字号、数据和状态；静态截图不能证明按钮行为。性能按首屏可交互、搜索、增量合并、首 token/事件、详情打开和后台资源分账，阈值在测基线后批准。辅助技术检查关注焦点和状态播报，不只是 ARIA 属性存在。

本轮没有运行这些未来 UI 测试，因为页面尚未实现；已完成的是证据核对、去重、研究文档和待办登记。
