# 生态调研 R10 · 输入预检与失败恢复

> 2026-10-14；基线：快门 v0.9.2，39 个 op / 22 个默认只读 MCP 工具。仅并行推进两个研究主题：执行前预检、执行后定位与恢复。
> 本轮依据官方文档形成 E1 资料证据，再与当前源码形成 E2 差距判断；实现、自动化、真实宿主和用户结果分别登记，不互相代替。

## 1. 官方机制与可迁移结论

| 产品与资料 | 可核实的机制（E1） | 对快门的推导与边界 |
|---|---|---|
| [QuickAdd CLI](https://quickadd.obsidian.guide/docs/Advanced/CLI/) | list 暴露捕获/模板的 writes 与 currentNote；check 检查缺失输入；外部调用可以明确当前笔记；verify 用于核实落地结果 | 将“参数齐全、上下文满足、确实写入”拆成不同检查。先评估现有 registry/config/editor.context 的组合预检，不增加通用读写业务库 |
| [Raycast Form](https://developers.raycast.com/api-reference/user-interface/form) | 字段有错误状态；验证正确格式与必填项；错误存在时不触发提交；变更后可消除旧错误 | 表单应在派发前拒绝 JSON 结构错型，并定位字段。校验源与 MCP 共用，避免同一输入在两个入口表现不同 |
| [Raycast Action Panel](https://manual.raycast.com/action-panel) | 选中项有上下文动作，主动作与辅助动作可由键盘操作 | 补齐快门无匹配时检查插件状态的独立入口；复制带参调用、查看说明等应与“立即执行”分离 |
| [Alfred Workflow Configuration](https://www.alfredapp.com/help/workflows/user-configuration/) | 工作流有作者、版本、说明与配置入口；未满足必要配置时突出提示 | 将“尚未配置”与“不可调用”分开显示；复用首跑、能力目录与设置入口，不新增另一套配置存储 |
| [n8n Error Handling](https://docs.n8n.io/flow-logic/error-handling/) | 失败数据关联 workflow、execution、lastNodeExecuted；重试包含 retryOf；触发阶段失败与执行阶段失败的结构不同 | 为回执/恢复增加关联来源与失败步骤候选。只借鉴定位信息；快门自动重试、后台规则与跨插件循环仍有幂等和用户证据门槛 |

这些机制对快门的优先价值是减少错误派发、解释不能执行的原因、保留失败关联。无需先扩大全量 op 或增加模型服务。

## 2. 已关闭的旧问题与新增证据

- R296 的“schema 驱动表单”已实现，但 `buildArgs` 对 array/object 只做 JSON.parse，合法 JSON 的对象、数组、null、标量可互相误入（E2）。关闭“能解析是否等于参数正确”的旧问题，晋升为本轮实现 A。
- TODO R71-P1 无匹配已注明缺少独立“检查插件状态”。Raycast 的辅助动作机制提供明确借鉴；快门已有诊断与生态页，复用该页即可补齐（E2），晋升为本轮实现 B。
- 10-14 主线 CI 日志与源码共同定位到平台判断屏蔽测试注入；本地发布包断链与计时抖动均有自动化证据。将这些列为开发基线任务，而非新功能候选。

## 3. 本轮登记的八项产品事项

| ID | 事项、优先级 | 验收与晋升条件 |
|---|---|---|
| R10-A | G3/P0 表单与 MCP 同源类型校验 | array 拒绝对象/null/标量，object 拒绝数组/null，number 拒绝非有限值；错误点名字段且零派发；合法 false/0/空数组仍可提交。本轮开发 |
| R10-B | G3/P1 无匹配时检查插件状态 | 有词/无词空态均出现独立动作，鼠标与键盘到达诊断生态页，默认不启桥、不写数据；导航数量同源。本轮开发 |
| R10-C | G3/P1 输入与上下文预检候选 | 先列所需参数、桥/插件和当前文档条件；使用现有只读能力组合；缺失时说明修复路径；执行前须再次检查，不能把预检成功当执行成功 |
| R10-D | G3/P1 写入影响描述补全 | 对有公开写入契约的精选 op 标明 owner、目标、读写、确认与结果证据；没有元数据时诚实显示未知；先以快速捕获样板验证后扩展 |
| R10-E | G2/P1 未完成配置提示卡 | 能力目录区别未安装、未启用、未配置、版本不兼容和读取失败；一键到对应设置；不读其他插件私有存储；依赖公开 ready/health 或快门自身设置 |
| R10-F | G5/P1 重试与失败步骤关联 | 回执保留原任务 ID、重试关联与最后完成步骤，部分完成不被总失败覆盖；协议字段先设计后改契约；自动重试仍需每步幂等与安全门 |
| R10-G | G3/P2 表单会话内暂存评估 | 本轮设计推导：参数填错/返回时保留尚未执行的输入；仅当前面板会话，不落盘，不复用已提交写入；关闭清除。真实反复填写反馈出现后晋升 |
| R10-H | G3/P1 复制带参调用示例 | 已验证参数可复制为明确标注的命令信封或工具调用示例；保留读写提示，禁止内嵌 Token/环境凭据；显式点击才复制，不自动执行或长期保存正文 |

R10-C/D/E/F/H 分别细化既有 G3 预检/预览、G2 修复入口、G5 恢复、R71 动作面板事项，不创建平行产品线。R10-G 是待验证设计推导，不宣称为 Raycast 已提供的具体功能。

## 4. 正式不立项结论

- 持久后台规则、失败后自动执行、跨插件循环：沿用 G5 治理锁定，触发条件为真实重复手动使用记录、逐步骤幂等和公开 owner 契约。
- 完整图形工作流编辑器与独立配置工作台：本轮不立项；只有现有工作流不能表达经过验证的任务，并有用户结果证据后再评估。
- 把上游 Capture 任意写入能力直接搬入快门：不立项；业务所有权与可核验结果优先，快门不复制其他插件私有数据。
