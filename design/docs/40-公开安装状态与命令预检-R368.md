# 公开安装状态与命令预检（R368，2026-10-14）

## 根因与来源

原生态目录和 registry.list 用 loadPetals 当安装表，读取失败又降级为空列表。这会把停用、不兼容或读取失败显示成未安装。上游 [SiYuan v3.8.6 LoadPetals](https://github.com/siyuan-note/siyuan/blob/v3.8.6/kernel/model/plugin.go) 会过滤停用、不兼容与发布受限项；遇到不允许安装的版本还可能调用 SetPetalEnabled，不能用作新预检的只读安装核验。

改用 [getInstalledPlugin 公共路由](https://github.com/siyuan-note/siyuan/blob/v3.8.6/kernel/api/bazaar.go) 的 `{frontend, keyword:""}` 请求与 `{packages}` 响应。其 [GetInstalledPackages](https://github.com/siyuan-note/siyuan/blob/v3.8.6/kernel/model/bazaar.go) 读取本地安装元数据，包括停用插件；字段为 `enabled`、`installedIncompatible` 和 `invalidReason`，不是 loadPetals 的 incompatible。只投影公开字段，不读取插件私有配置，不加载业务代码。

上游文件系统扫描错误仍可能在服务端被收敛为空列表；API 未列出不能证明物理目录不存在。因此 UI 使用“安装清单未列出”，不将该结果扩大成完整文件系统审计，也不绕过 API 读取私有存储。

## 已实现行为

- 前端、内核和生态目录共用安装核验：已安装启用、已安装停用、宿主不兼容、安装包异常、状态未核验和读取失败分别保留。版本缺失不代表未安装，版本漂移不等于协议不兼容。
- registry.list 保留静态 manifest 和 recorded 回执；安装核验失败时 `installed=null`，并附 installation.status/error/source/checkedAt。旧消费者应判断 `installed===true`，不能用 `!installed` 推断缺席。
- 参数表单增加“检查调用条件”，执行前始终重新检查。21 个精选表单检查输入和快门桥，其中 18 个生态 op 再查安装/启用、公开协议和对应方法；打卡额外检查 hasCapability/isReady。另外三个快门 op 的业务目标仍由执行层核验。
- 检查不调用业务方法、whenReady、模型服务或写 API，不预约信封，不写回执、审计或正文。公开接口没有提供的业务配置标成“未核验”；通过只代表已核验条件，不能据此声称业务成功。黑名单、确认和权限仍由原派发层负责。
- 检查期间冻结输入，返回/关闭取消后续派发；迟到报告按表单代次丢弃，连续确认只派发一次。未知回执或派发异常关闭该表单的再次提交入口，先人工核对回执和目标。
- 安装核验最多等待 5 秒，超时不重发、迟到结果不改写报告。修复入口分别到快门连接页、诊断页；上游插件启用/配置仍由用户在思源已下载插件页核对。
- 生态目录限制高度并滚动内容，八插件长列表的关闭按钮保持可见。

## 人脉协议漂移

本机安装产物仍标版本 0.5.5，但公开桥声明 protocol=2（E2 静态产物，不等于运行中桥 E4）。上游本地 docs/BRIDGE.md 与 src/bridge/external-bridge.ts 明确要求精确匹配主版本：v2 建人必须提供稳定 ref 或明确 docId，姓名不再自动选人；互动含逐项失败/unknown，不能按 v1 全部映射 recorded。

现有 contacts 适配只支持 v1，本轮在三项 adapter 入口统一检查 protocol=1，覆盖 MCP/NDJSON/广播/表单；不兼容版本零业务调用并返回 unsupported。v2 适配登记独立 P0，需先更新输入/回执契约与稳定请求身份，不实现隐式降级开关。

可复核的安装编译产物 SHA-256：打卡 18.17.2 `780727e554b52f5288e38357581dd770d66a392f4c34cf21af8eb7b45bd70735`（公开版本字段为 version=5）；人脉 0.5.5 `e65a8c5f104825ef85c5f8874d95268e41131c86fbfccfbc2c4c3e76867f3371`（protocol=2）。安装版本相同不能替代协议字段校验。
