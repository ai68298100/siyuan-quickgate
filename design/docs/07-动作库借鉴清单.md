## 1. 总体洞察（决定我们的差异化定位）

1. **热度最高的不是 API 集成，而是「界面补丁」**：榜首「置顶」（窗口置顶+边框提示，223 赞 1966 用户）、zxerath 的系列字体颜色动作（红/蓝/橙/粉各一个独立动作，合计高赞）、彩虹色标注……都是在补思源 UI 的易用性短板，与思源内核几乎零交互。
   → **启示**：① 这类动作每个颜色一个动作是碎片化的，我们的超级面板一个菜单就能收纳同类功能（或经快门调思源自带命令）；② 真正的 API 深度集成（快摘/快查/Zotero 系/豆瓣）用户基数小但粘性高——正是我们+快门的生态位，竞争者少。
2. **分类里混着大量「适用于思源」的通用动作**（置顶是微信/SiYuan 两用的窗口工具）。
   → **启示**：评估借鉴对象时先看它是否真的走了思源 API。
3. **活跃的「思源 API 动作」头部作者**：浅沧（无效数据处理/汇总日记代办/豆瓣入库/工作空间系列/图片OCR/截图注释外链）、寒Orz（快摘/快查，2025-12 仍在更新）、shuoying（Markdown图片OCR搜索/Zotero PDF双向链接）、ttChen（Zotero 文献全家桶）、何舜人（Siyuan速记）。
   → **启示**：他们的动作是最贴近「可运行参考实现」的素材；寒Orz 两个动作的输入兜底/内容分派设计与我们 P0 蓝图高度同构，可直接对齐。

## 5. 与「小驴快门」联动的新机会（本次调研发现）

1. **浅沧系列的多工作空间痛点**（豆瓣入库明说「不支持多工作空间」）——快门桥天然按工作空间隔离，超级面板+快门可做成多空间感知的启动器（T10/T11 的窗口管理与快门 ping 结合）。
2. **「取 token」公共子动作**（Runos 使用）说明社区已有动作间复用惯例——我们把 `SY·内核请求` 做成公开子程序分享，可被他人动作引用，扩大生态影响。
3. **桥类动作的安装向导是标配**（Zotero Debug Bridge 向导）——快门发布时配套「一键开桥向导」动作（检测桥状态→引导开启→ping 验证），降低 L3 门槛。
4. **编译 DLL 提速**（超级卡片）——若超级面板 C# 构建菜单变慢，参照此法把热路径编译为 DLL。
