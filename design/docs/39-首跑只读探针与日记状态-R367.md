# 首跑只读探针与日记状态（R367，2026-10-14）

## 问题与处理

原 `readDailyStatus` 按标题包含日期检索，并将 SQL 异常返回为 `exists=false`。这会混淆普通日期标题文档、未创建日记和读取失败。现改为查询思源原生 `custom-dailynote-YYYYMMDD` 属性，返回文档 ID；只有合法的空结果表示未创建，读取异常和坏响应交给调用方处理。

字段对齐 [SiYuan v3.8.6 CreateDailyNote](https://github.com/siyuan-note/siyuan/blob/v3.8.6/kernel/model/file.go) 的属性写入与 [属性表](https://github.com/siyuan-note/siyuan/blob/v3.8.6/kernel/sql/attribute.go)。对外成功数据仍为 `{docId, exists}`，无新增 op；桥将读取异常记为 failed，不制造“日记不存在”的成功回执。日期依照当前客户端日期，多个匹配时按 ID 稳定选取一个；它不是对捕获目标笔记本的锁定或完整日记目录。

人工日期标题、尚未带原生属性的文档不据标题推断成日记，也不自动补属性。若用户需要识别这类既有日记，先明确公开识别规则和真实样本，再评估兼容方案。

首跑步骤 5 显示实际失败原因、耗时、通道与可复制 JSON 证据；成功与失败都可复制。重试期间单飞，改配置/FAQ 继续复用既有入口；不把该直接内核读取解释为外部桥已验收。原 L570 继续部分完成：实际首跑允许显式跳过，不能将可跳过的流程强行记作“必须完成只读探针”已满足。
