# 36 · 长任务取消规格（L572 · workflow.cancel）

> 2026-10-07。规格先行（E2）。**实现绑定门槛：docs/28 §6 取消逐项表确认 + workflow 真实使用**——规格定稿 ≠ 立即实现。
> 现状基线：`src/services/workflow.ts`（plan→总确认→逐步执行→失败停止，≤8 步，已完成步骤不回滚）+ 确认窗 30s 超时拒绝（index.ts confirmWithFront）+ 迟到完成如实标注（已实现 ✅）。

## 1. 现状语义盘点（docs/28 §6 逐项表 · 全部已实现 ✅）

| 阶段 | 可否取消 | 现状 |
|---|---|---|
| 确认窗等待（30s） | ✅ | 超时即拒绝；用户可点取消 |
| 单步内核执行中 | ❌ 不可中断 | 思源内核无 op 级取消 API；单写 op 原子性由内核保证 |
| 步骤间（下一步开始前） | ❌ 无通道 | execute 循环一口气跑完，无外部取消标志检查 |
| 迟到完成 | ❌ 不可取消 | 已先行回执 failed——只能如实标注，不得改写 |
| 失败停止后 | — | 已完成步骤不回滚（补偿=人工思源快照） |

## 2. 目标与非目标

**目标**（TODO L572）：给「步骤间」补上取消通道——`workflow.cancel` op：用户（或同 id 发起方）在 workflow.execute 运行中请求取消，执行器在**下一步骤开始前**停止（已完成的步骤保留，不回滚，回执如实标注"用户取消于第 N 步前"）。

**非目标**：
- 不中断正在执行的内核 op（技术上不可行——思源无取消 API；语义上单写 op 原子，中断=脏数据风险）。执行中的当前步骤**必须跑完**。
- 不做已完成步骤的自动回滚（与"失败不回滚"补偿边界一致）。
- 不做通用任务管理器（只覆盖 workflow.execute；单 op 命令本就是秒级）。

## 3. 设计

### 3.1 取消通道：取消文件（与队列同范式）

- 路径：`/storage/petal/siyuan-quickgate/bridge/cancel.json`，形状 `{ schemaVersion: 1, planId: string, requestedBy: "user"|"external", requestedAt: ISO }`。
- 发起：面板恢复向导/CLI 写入（与 commands.ndjson 同样的 append/覆写纪律——单写者=设置面板，无并发问题）。
- 检查点：workflow.execute 循环**每步开始前**与确认窗弹出前各检查一次；命中同 planId → 停止，回执标注 `stopped: "user-cancel"`，已完成步骤列表照常输出。
- 竞态边界：检查与执行之间存在毫秒级竞窗（当前步骤不可中断是硬边界）——回执如实呈现，文档不承诺"精确到步"。

### 3.2 op 面（契约新增 1 个 op，24 个）

- `workflow.cancel { planId }` → recorded（无论运行中与否，幂等：已停止再取消仍 recorded）。
- 走标准信封通道（三通道均可发）；**不新增白名单外能力**。

### 3.3 回执与恢复联动

- 取消后的运行回执：`status: "recorded"`，`data: { stopped: "user-cancel", completedSteps: [...], pendingSteps: [...] }`——pending 步骤可重新 plan 后执行（计划参数不变时人工重发）。
- 恢复中心联动：取消不是失败，不进 unknown/失败恢复列表。

## 4. 边界

| 场景 | 行为 |
|------|------|
| 取消到达时全部步骤已完成 | recorded，data 注明 "already-completed" |
| planId 不存在/已过期 | recorded，data 注明 no-match（幂等，不报错） |
| cancel.json 损坏 | 忽略（等同无取消请求），载体明细卡可查 |
| 确认窗等待中取消 | 确认窗 30s 语义不变；cancel.json 只作用于 execute 循环 |

## 5. 验收标准

1. 三步计划执行中途写入 cancel → 第 N 步后停止，回执含 completed/pending 步骤列表与 user-cancel 标注。
2. 已完成步骤的数据保留（不回滚）——思源中可核验。
3. 全部步骤完成后再取消 → recorded + already-completed。
4. 取消不进恢复中心列表。
5. 不开桥（MCP 只读）时 workflow.cancel 不可用——如实（写 op）。
