# 生态调研 R6 · 命令面板/启动器交互范式（喂 G3-01 统一命令面板）

> 循环 C 第 6 轮（2026-10-06）。对象：Raycast、uTools、PowerToys Run、Alfred、Obsidian QuickAdd/Commander。
> 结论服务于快门 G3-01（统一命令面板）与 G3-02（显示/执行/能力分离）；只立项可实现项，不复制不可验证的宣传。

## 1. 各家机制速览

| 产品 | 核心交互 | 对快门可借鉴点 |
|---|---|---|
| Raycast | 单输入框 fuzzy 搜索；命令可声明**参数 schema**（textfield/dropdown），回车进入参数面板再执行；每命令可设别名与热键；无结果时显示 **fallback commands**（自定义兜底动作） | 参数化命令二段式执行；fallback 兜底 |
| uTools | 全局关键词触发（输入特定词直接进入插件功能）；超级面板（选区呼出）；插件内「命令」注册表集中管理 | 关键词别名触发（快门 search-alias 已有同构） |
| PowerToys Run | 前缀触发（`=` 计算、`<` 文件……）；结果列直接内联预览；上下文动作（次级行动作） | 前缀分域可后置；结果行的次级动作（打开原文/复制）|
| Alfred | Workflow 的 keyword+argument 流；Universal Action 对选区串联多步 | 选区为第一输入源的串联（G3-04 捕获同构） |
| Obsidian QuickAdd | 命令=宏（多步 chain），每步可选「确认再继续」；Commander 把命令挂到任意 UI 位 | 宏=快门 workflow 的用户语言；挂载位映射到 Quicker |

## 2. 交叉结论（G3-01 落地排序）

1. **二段式参数化**是各家共同点：命令先列出来（可搜索），参数在回车后收集——快门的 op 参数 schema 已存在于 manifests/契约，做"列表→参数面板"二段即可复用，不需要新协议。
2. **fallback 兜底**是空态纪律的启动器版：无匹配时给"捕获到收集箱 / 打开健康页 / 导出诊断包"三个兜底动作，避免死面板（与 G2-03 同源）。
3. **别名三层**：拼音/中英（已有）+ 用户自定义别名（favorites 置顶已覆盖高频）+ 关键词直触发（Quicker 侧已有关键词）——面板内无需再造第四层。
4. **确认语义不进面板**：各家执行型动作的确认都在"参数面板之后"而不是列表 hover——与快门 confirmExec 门控一致，不学 hover-执行。

## 3. 立项建议（本轮登记 2 条，进 §19/经验池）

- **R6-A【评估→G3-01】参数化命令二段式**：面板列出命令 → 回车出参数面板（schema 由 manifest capabilities 推导，字段级 confirm 标注沿用 G3-03）；验收=一次 schema 驱动渲染 + 取消无副作用。
- **R6-B【评估→G3-01】fallback 兜底动作**：无匹配/无能力时展示捕获、健康页、诊断包三兜底（全部走已交付能力，无新 op）；验收=空态三按钮可用。
- 不立项：前缀分域（快门命令量级不需要）、悬浮超级面板（Quicker 侧职责）。
