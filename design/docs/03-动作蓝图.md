# 首批 Quicker 动作蓝图

> 约定：所有动作的用户配置项（Quicker「动作设置 → 用户配置」）：`SY_URL`（默认 `http://127.0.0.1:6806`，思源默认端口）、`SY_TOKEN`、`收集箱文档ID`、`日记笔记本ID`。
> 通用前缀：动作内部先用「读取文件」模块读 `%APPDATA%\siyuan\env` 解析 `SIYUAN_URL/SIYUAN_TOKEN` 作为配置缺省值。
> 请求体里的 `{文本}` 是 Quicker 变量插值；`$= ...` 是 C# 表达式。
> 所有端点与参数已按 [04-内核API速查](04-内核API速查.md) 核实；错误处理统一见 04 §8，动作内不重复写。

## 0. 共享规范（所有动作适用）

**共享子程序**（Quicker「子程序/链接动作」，一处维护处处生效）：

| 子程序 | 职责 |
|---|---|
| `SY·内核请求` | 唯一内核调用入口：读配置 → HTTP → 通用错误分支（401 令牌引导 / 超时「思源未运行」/ busy 重试 / not exist 提示重配） |
| `LV·发命令` / `LV·取回执` | 02 桥协议 §6 的逐步规范 |
| `SY·路由` | 超级面板分发器（05 §5）；独立动作可不经过它 |

**每个动作的固定骨架**：①配置就绪检查（statestorage 有无 sy_token）→ ②version 探测（300ms，失败走「思源未运行」分支）→ ③业务步骤 → ④notify 中文反馈（成功说结果，失败说原因+下一步）。任何动作不超过 3 层嵌套，复杂逻辑下沉到子程序。

**划词类动作的输入优先级**（对齐动作库「快查/快摘」的成熟设计，见 [07-动作库借鉴清单](07-动作库借鉴清单.md) T3）：Quicker 搜索框参数 → 思源前台选中文本 → 剪贴板 → userinput 弹窗（四级兜底，任何一级有值即用）。

**两条插入位置的铁律**（借鉴 Zotero 系动作）：
- API `appendBlock` 只能追加到文末/容器——无人值守场景（捕获、汇总）用它。
- 要插到**光标处**（编辑场景）：写剪贴板 → 激活思源 → 模拟 Ctrl+V（保格式）。两者按场景选，别混用。

**写入后立刻要引用新块 ID 的动作**：等 **2s** 或对 `getBlockInfo` 做最多 3 次重试（思源索引异步入库——**R140 实测校准（2026-10-04，后台自动化）**：insertBlock 写入 62ms 后，SQL 可见需 **≈1.8s**、getBlockInfo 立即可用；「等 1s」偏紧，SQL 查询场景按 2s 或 3 次重试设计。外部实测「操作太快会出错」——文献列表作者的踩坑记录，同 04 §7.3）。

**配置自动发现（08-O13，尽量不让用户手填 ID）**：
- 日记笔记本：遍历 `/api/notebook/getNotebookConf` 读 `dailynoteSavePath` 自动判定（字段名以快门 spike ⑧ 为准）；失败回退用户配置。
- 收集箱：约定优先——名为「收集箱/Inbox」的笔记本根文档；无则回退用户配置。
- 首次运行向导改为「自动发现 → 展示结果让用户确认/改」三步（SY·诊断报告发现明细）。

**文本指令注册表**（统一前缀风格，避免冲突）：

| 指令 | 动作 | 指令 | 动作 |
|---|---|---|---|
| `syq` | 超级面板 | `dk` | 一键打卡 |
| `sy` | 全局快查 | `rm` | 记人脉互动 |
| `jl` | 记一笔到日记 | `db` | 汇总日记待办 |
| `zl` | 划词摘录 | `tj` | 数据体检 |
| `fj` | 分拣收集箱（R11） | | |

**反馈文案规范**：`✓ 成功+结果摘要` / `✗ 失败+原因+下一步` / `⏳ 已提交，思源忙，稍后在通知里看结果`（异步桥命令）。所有动作统一，分享截图也展示这套。

**捕获多目标路由（R3，源自 QuickAdd Capture 对标，docs/10 §2-①）**：快速捕获/摘录支持「路由规则表」——`默认 → 日记`；`#会议 前缀 → 会议笔记本`；`@人名 → 收集箱 + 人脉互动`。输入后按前缀匹配（规则表存动作状态，右键菜单可编辑）；无匹配走默认。v1 只做前缀路由不做正则；命中 `@人名` 时顺带走人脉桥 `contacts.interaction`。

## P0-1 快速捕获到今日日记 ⭐ 首发

**触发**：全局快捷键（建议 `Alt+S`）或 PowerKeys（连按两次 Shift）
**步骤**：

1. `userinput`：多行输入框，标题「记点什么」，保存到文本变量 `内容`
2. `HTTP 请求`：
   - 网址：`{SY_URL}/api/block/appendDailyNoteBlock`
   - 方法 POST · 请求体类型 JSON · 内容类型 `application/json` · 超时 10s
   - 请求体：`$= JsonConvert.SerializeObject(new { notebook = {日记笔记本ID}, dataType = "markdown", data = "- " + DateTime.Now.ToString("HH:mm ") + {内容} })`
3. `if`：状态码 ≠ 200 或响应 `code≠0` → `msgbox` 报错
4. `notify`：`✓ 已入今日日记`

> `appendDailyNoteBlock` 自带「今日日记不存在则创建」，无需预检。多块 markdown 可一次追加（标题/列表/代码块都行）。

**变体：追加到指定标题下（R6，对标 Obsidian Advanced URI 的 heading 定位追加）**：落点三级可选（动作右键设置）：①指定标题（默认）②文末 ③收集箱。实现：
1. `HTTP` → `/api/query/sql`：`SELECT id FROM blocks WHERE root_id=(今日日记 root_id) AND type='h' AND content LIKE '%{目标标题}%' ORDER BY id LIMIT 1` → `标题块ID`（零命中回退文末并 notify 说明）
2. `HTTP` → `/api/block/appendBlock`：`parentID = {标题块ID}`（其余同主流程）
> appendBlock 追加为该容器块的**最后一个子块**，标题块即其节区容器——语义与 Advanced URI `heading` 参数一致。注意 SQL 对 `{目标标题}` 做单引号转义。

## P0-2 划词摘录到收集箱

**触发**：划词工具条按钮（+ 思源前台的程序快捷键）
**步骤**：

1. 输入按 §0 四级兜底 → `选中文本`；`getwindowtitle` 取来源窗口 → `来源`（浏览器前台时经 Quicker 浏览器扩展拿页面 URL，快摘同款）
2. `userinput`（可选）：一句话备注 → `备注`；内容判型（借鉴快摘）：图片链接→`![](url)`、纯链接→iframe 内嵌块、文本→引用块
3. `HTTP 请求` → `{SY_URL}/api/block/appendBlock`：
   `$= JsonConvert.SerializeObject(new { data = "> " + {选中文本}.Replace("\n","\n> ") + "\n\n-- 摘自 " + {来源} + " · " + DateTime.Now.ToString("yyyy-MM-dd HH:mm") + ({备注}==""?"":" · "+{备注}), dataType = "markdown", parentID = {收集箱文档ID} })`
4. `jsonextract`：取新块 ID（`data[0].doOperations[0].id`）→（可选）`writeclipboard siyuan://blocks/{块ID}`——双向链接闭环第一半（借鉴 Zotero PDF🔗思源），等 1s 再用（索引延迟）
5. `notify`：`✓ 已摘录到收集箱`

> 想带原始网页 URL 时，浏览器动作可用浏览器扩展传递当前页 URL 变量。

## P0-3 思源全局快查

**触发**：文本指令 `sy`；或全局快捷键
**步骤**：

1. 输入按 §0 四级兜底 → `关键词`
2. `HTTP 请求` → `{SY_URL}/api/search/fullTextSearchBlock`：
   `$= JsonConvert.SerializeObject(new { query = {关键词} })`
   **AI 增强**（借鉴快查，08-O6 调整）：`关键词` 以 `sql:` 开头时进入实验分支：调用思源内置 AI（`/api/ai/chatGPT`，复用用户已配好的思源 AI）→ 提取模型文本 → 只允许单条 `SELECT/EXPLAIN` → 强制 `LIMIT` → `/api/query/sql`。当前端点请求/响应形状仍需 M0 实测，AI 失败或校验不通过时回退普通关键词搜索；Quicker AI 模块仅作思源 AI 未配置时的备选。
   **fallback 链（R3，源自 PowerToys Run fallback，docs/10 §2-④）**：全文搜索零命中 → 自动改跑同名 SQL（`SELECT id,content FROM blocks WHERE content LIKE '%关键词%' AND type='p' LIMIT 20`）→ 仍零命中 → 提示「加 `sql:` 前缀用 AI 生成查询」。三级串联，用户无感降级。
3. `jsonextract`：从文本结果提取 `data.blocks[*].{id,content}` → 列表变量
4. `userselect`（列表选择）：展示内容摘要+更新时间 → 选中 → `块ID`（结果多时升级为 showtext 自定义窗口，快查同款）
5. `openurl`：`siyuan://blocks/{块ID}` → 思源跳转并高亮该块

> 想要精确查询（标题/标签/自定义属性）把第 2 步换成 `/api/query/sql`：`SELECT id,content FROM blocks WHERE content LIKE '%{关键词}%' AND type='p' LIMIT 20`（注意对 `'` 转义，思源 SQL 无占位符）。

## P0-5 剪贴板图片存入思源

**触发**：思源场景页按钮 / 快捷键
**步骤**：

1. `getclipboardimage` → 图片变量 `图`
2. `HTTP 请求`（请求体类型 **MultiPart 表单**）→ `{SY_URL}/api/asset/upload`：
   - `file` = `IMG:{图}`（Quicker 图片变量写法）
   - `assetDir` = `/assets/`、`syzmo` 之类按需
3. `jsonextract`：取 `data.succSet[0].path` → `资源路径`
4. （可选，借鉴「Markdown 图片内容搜索」）Quicker OCR 模块识别 `图` → `OCR文本`；中文结果做清理（去汉字间空格换行）

   —— **OCR 结果写进 alt 文本**，思源搜不到图片内容但能搜 alt，图片从此可被全文检索命中

## SY-12 汇总日记待办（借鉴「汇总日记代办」，纯内核）

**触发**：文本指令 `db` / 快捷键 / 超级面板 📝 组
**步骤**：

1. `userinput`：回看天数（右键菜单记忆，默认 7）→ `天数`
2. `HTTP 请求` → `/api/query/sql`：聚合最近 N 天日记文档里的未勾选待办。先在 C# 中按本地日期生成最近 `天数` 个 `yyyy-MM-dd` 白名单谓词（每个日期只做 `LIKE '%yyyy-MM-dd%'`，并对日期做固定格式校验），再绑定日记笔记本 `box`：
   `$= JsonConvert.SerializeObject(new { stmt = "SELECT b.id, b.content, b.root_id FROM blocks b JOIN blocks d ON b.root_id=d.id WHERE d.type='d' AND d.box='" + {日记笔记本ID} + "' AND (" + {日期谓词} + ") AND b.markdown LIKE '%[ ]%' ORDER BY b.id DESC LIMIT 100" })`
   （不得使用 `LIKE '%20%'` 这类宽匹配；笔记本 ID 只能来自自动发现或已确认配置，SQL 仍需做单引号转义。）
3. `jsonextract` → 列表 → `userselect` 多选确认（或全选）
4. `HTTP 请求` → `appendDailyNoteBlock` 写汇总块到今日日记：`## 待办汇总（近{天数}天）` + 每条 `- [ ] 内容 [链接](siyuan://blocks/{id})`
5. `notify`：`✓ 已汇总 {N} 条待办`

> 教训（来自原作讨论区）：只统计日记文档里的待办，别全库扫；范围判定用「日记标题含日期」约定。

## SY-13 数据体检（借鉴「无效数据处理」，只读版）

**触发**：超级面板 ⚙️ 组 / 文本指令 `tj`
**步骤**：

1. `showmenu` 选体检项：空文档 / 重复标题文档 / 失效块引用 / 长期未更新文档
2. 各项对应只读 SQL：
   - 空文档：`SELECT id,content FROM blocks WHERE type='d' AND content='' LIMIT 50`
   - 重复标题：`SELECT content, COUNT(*) c FROM blocks WHERE type='d' GROUP BY content HAVING c>1 LIMIT 50`
   - 长期未更新：`SELECT id,content FROM blocks WHERE type='d' AND box='<笔记本>' ORDER BY id ASC LIMIT 50`（id 前缀是创建时间）
3. 结果 `showtext` 报表（数量+样例+siyuan:// 链接），**不自动删除任何东西**
4. 清理动作提示用户使用原作「无效数据处理」（成熟度高，我们不重复造轮子——07 §T17 同理）

> 原作踩坑教训（只读版也要注意）：已关闭笔记本、嵌入块内引用、AV 绑定文档都容易误判——报表加「可能误判」提示。

## P1-7 一键打卡（快门优先，旧桥兜底）

**触发**：全局快捷键 / PowerKeys
**步骤**：

1. 首选 `LV·发命令` → 插件 `siyuan-quickgate`，op=`checkin.items`，args=`{includeArchived:false,limit:50}`；只有快门缺席且用户明确启用旧桥时，才投递 `siyuan-checkin/items.list`
2. `LV·取回执` → 列出 `{items}`（id/name/unit）
3. `userselect`：展示事项名 → `选中事项`
4. `LV·发命令` → 快门 op=`checkin.record`，args=`{itemId:{选中事项.id}, value:1, note:"Quicker 一键打卡"}`（由输入信封 id 派生 externalRef，天然幂等）
5. `LV·取回执` → 快门 op=`checkin.summary`，args=`{itemId}`
6. `notify`：`✓ 已打卡 {事项名} · 连续 {streak} 天`

## P1-8 记一笔人脉互动（快门优先，旧桥兜底）

**触发**：全局快捷键（会面结束时按）
**步骤**：

1. `userinput`：`参与人（逗号分隔）`
2. `userinput`（可选）：`地点`、`备注`
3. 首选 `LV·发命令` → 插件 `siyuan-quickgate`，op=`contacts.interaction`：

## P1-9 专注结束自动打卡

**触发**：本动作启动即开始计时（或由番茄类程序经 `/api/exec` 触发）
**步骤**：

1. `userinput`：专注分钟数 → `分钟`
2. `wait`（或系统计时）→ 结束提示音
3. `LV·发命令` → 快门 `checkin.record`，args=`{itemId:{绑定事项}, value:{分钟}, unit:"分钟"}`
4. 失败/超时 → `writetextfile` 追加到 `%TEMP%\quicker-pending-checkin.ndjson`，下次运行动作时先重发（离线兜底）

## P2-10 手机快捷指令远程捕获

**触发**：iOS 快捷指令 / Android HTTP Request
**请求**：

```http
POST http://<PC内网IP>:668/api/exec
Authorization: Bearer <Quicker令牌>
Content-Type: application/json

{ "operation": "action", "id": "<快速捕获动作ID或名称>",
  "inputs": { "内容": "刚开会定的三件事…" }, "wait": true, "maxWaitMs": 15000 }
```

**动作改造**：P0-1 增加「入参优先」分支——`文本指令入参/quickcapture` 输入变量非空时跳过 `userinput`，直接入库并 `notify`。
**注意**：668 服务需在 Quicker 设置里开启；建议勾选 HTTPS 与访问令牌；`operation=action` 的确切字段名以 [官方文档](https://docs.getquicker.net/v2/features/http-websocket/) 为准（V2 持续演进中）。
> **社区实证（R7）**：动作库 [「Siyuan速记」](https://getquicker.net/Sharedaction?code=d9cab944-b742-4d0b-d9c6-08de9917e55e)（何舜人，v4）已验证同款链路——iOS 快捷指令 → `POST :668/api/exec` → 电脑动作 → 思源 API 落库，且公开分享了快捷指令配置方法。本蓝图的技术路线**可行性已被社区验证**；差异化价值=我们的动作带四级兜底/多目标路由/快门审计，且经快门桥可回执确认（对方是 fire-and-forget）。另见 [思源官方 issue #14414](https://github.com/siyuan-note/siyuan/issues/14414)（移动端"闪念速记"官方路线，落 `~/.config/siyuan/shortcuts/shorthands/*.md`）——若官方落地，可作快门 events/file 载体的另一个数据源。
> **移动端跳转（R12）**：手机端 `siyuan://blocks/<id>` 已可从外部打开（官方 [#14799](https://github.com/siyuan-note/siyuan/issues/14799) 已完成；安卓经 boot activity 有加载界面）——快捷指令在回执通知里附 `siyuan://blocks/{日记ID}`，点开即见刚写入的块。

## 附A：AI 写动作提示词（Quicker 2.2.0+，暂存区「用 AI 写」直接粘贴）

> 用法：Quicker 暂存区 →「用 AI 写」→ 粘贴对应提示词 → AI 生成动作后**按蓝图核对**（AI 不了解思源 API 细节，HTTP 网址/请求体以本蓝图为准）。生成后先在测试模式跑通再启用快捷键。`SY_URL`/`SY_TOKEN`/`日记笔记本ID` 等变量在动作「用户配置」里建好后替换引用。

**P0-1 快速捕获到今日日记：**

```
创建 Quicker 动作「记到思源日记」：①userinput 多行输入框，标题"记点什么"，结果存文本变量 内容；②HTTP 请求模块 POST 到 {SY_URL}/api/block/appendDailyNoteBlock，请求体类型 JSON，内容 $= JsonConvert.SerializeObject(new { notebook = {日记笔记本ID}, dataType = "markdown", data = "- " + DateTime.Now.ToString("HH:mm ") + {内容} })，超时 10 秒；③if 判断状态码不是 200 或响应里 code 不是 0，则 msgbox 显示"思源未运行或令牌无效"，动作结束；④成功则 notify 显示"✓ 已入今日日记"。SY_URL 和 日记笔记本ID 是动作用户配置里的文本变量。
```

**P0-2 划词摘录到收集箱：**

```
创建 Quicker 动作「摘录到思源收集箱」：①取输入文本存变量 选中文本：优先动作传参，其次当前选中文本，再剪贴板，都为空则 userinput 弹窗输入；②getwindowtitle 取前台窗口标题存 来源；③HTTP 请求 POST {SY_URL}/api/block/appendBlock，请求体 $= JsonConvert.SerializeObject(new { data = "> " + {选中文本}.Replace("\n","\n> ") + "\n\n-- 摘自 " + {来源} + " · " + DateTime.Now.ToString("yyyy-MM-dd HH:mm"), dataType = "markdown", parentID = {收集箱文档ID} })；④失败时 msgbox 提示，成功时 notify "✓ 已摘录到收集箱"。收集箱文档ID 来自动作用户配置。
```

**P0-3 思源全局快查：**

```
创建 Quicker 动作「思源快查」：①取输入存 关键词（动作传参→选中文本→剪贴板→userinput 四级兜底）；②HTTP 请求 POST {SY_URL}/api/search/fullTextSearchBlock，请求体 $= JsonConvert.SerializeObject(new { query = {关键词} })；③用 jsonextract 提取 data.blocks 数组每项的 id 和 content 生成列表；④userselect 展示列表让用户选一条，选中项的 id 存 块ID；没选或无结果则动作结束；⑤openurl 打开 siyuan://blocks/{块ID}。失败时 msgbox 提示"思源未运行或令牌无效"。
```

**P0-4 打开今日日记：**

```
创建 Quicker 动作「打开今日日记」：①HTTP 请求 POST {SY_URL}/api/query/sql，请求体 $= JsonConvert.SerializeObject(new { stmt = "SELECT root_id FROM blocks WHERE type='d' AND content LIKE '%" + DateTime.Now.ToString("yyyy-MM-dd") + "%' LIMIT 1" })；②jsonextract 取 data[0].root_id 存 日记ID；查不到则 notify "今天还没有日记，先用捕获动作记一笔吧" 并结束；③openurl 打开 siyuan://blocks/{日记ID}。SY_URL 来自动作用户配置。
```

**P0-5 剪贴板图片存入思源：**

```
创建 Quicker 动作「剪贴板图片存思源」：①getclipboardimage 取剪贴板图片存图片变量 图，为空则 notify "剪贴板里没有图片" 并结束；②HTTP 请求 POST {SY_URL}/api/asset/upload，请求体类型 MultiPart 表单，字段 file 值为图片变量 图（IMG: 前缀写法），字段 assetDir 值 "/assets/"；③jsonextract 取 data.succSet[0].path 存 资源路径；④HTTP 请求 POST {SY_URL}/api/block/appendDailyNoteBlock，请求体 $= JsonConvert.SerializeObject(new { notebook = {日记笔记本ID}, dataType = "markdown", data = "![剪贴板 " + DateTime.Now.ToString("MM-dd HH:mm") + "](" + {资源路径} + ")" })；⑤notify "✓ 图片已入今日日记"。
```

**P0-6 场景页**：不是动作，是 Quicker 场景配置（新建「SiYuan」场景绑定 siyuan.exe，把上面动作加入场景页），无需 AI 生成。

> 提示词生成的是**骨架**：四级输入兜底、错误分支细化、状态存储、多目标路由等仍按 §0 蓝图人工补齐；AI 生成的 HTTP 网址/字段名务必与蓝图逐字核对。「追加到指定标题」变体（P0-1 节）暂不提供提示词——先让 AI 生成主流程骨架，变体分支（SQL 定位标题块）人工追加更稳。

### 附A.1 结构化生成模板与约束（R110-P0，AI 生成动作的授权与门禁）

**结构化模板八字段**（每个动作的提示词都应覆盖；上列 P0-1~P0-5 即此结构的实例）：

```
【用户结果】一句话说明动作完成后用户得到什么（非模块步骤）
【输入】来源（选区/剪贴板/参数/文件）+ 类型 + 空输入路径
【输出】变量名/类型 + 去向（思源写入/剪贴板/仅展示）
【目标】写入位置（文档/块/资产目录）+ owner（哪个插件是数据权威）
【约束】只使用：登记模块清单、快门公开 op（docs/api.md）、reference/ 参考子程序、qk 公开 API
【错误】网络/鉴权/目标缺失/插件未就绪/业务拒绝/超时/未知 → 各给下一步（对齐 FAQ）
【回执】完成判据五级（ACTION-CARDS 文末）：notify≠证据，以回执 data 为准
【版本】目标 Quicker 版本（2.2.0+）/参考件版本/蓝图版本（docs/03 HEAD）
```

**生成约束（R110-P0·生成约束）**——AI 只允许使用以下三类能力，出现清单外方法/私有路径即拒绝生成并保留草稿：
1. **模块白名单**：Quicker 常规模块（userinput/http/jsonextract/userselect/openurl/showMessage/msgbox/getclipboardimage/getwindowtitle/writeclipboard/模拟按键）；
2. **快门公开 op**：docs/api.md 全表（23 op；`plugin.api` 默认关，生成物**不得引用**）；
3. **参考子程序**：`reference/` 19 件（按 ACTION-CARDS 速查表引用，不重造）。

**模块幻觉门（R110-P1）**：生成的 C# 片段可投 **csc 编译门**静态验证（`reference/__build-compile.mjs` + csc）——不存在的模块/错误 API 在编译期暴露而非运行时（已有 27 脚本 27/27 通过的运行先例）；Quicker 模块名合法性按生成约束清单人工核对。

**授权分离（R110-P0·生成不授权）**：生成代码 ≠ 保存动作 ≠ 运行动作 ≠ 写入思源 ≠ 外发通知——五步各自确认；AI 回复的"已完成/已保存"句式**不构成授权事实**（红线：未知不得改写为成功）。MCP/外部助手同构：`LV_MCP_WRITE` 门控 + 快门确认门控分立。

**暂存隔离（R110-P0）**：AI 新建动作默认进 Quicker 暂存区（原生能力），显示暂存 ID/来源/时间；未「保留到场景」不进稳定目录——与本仓库分发方式（reference/ 参考 + .qa 导出）天然兼容。

## 附：Token/端口配置的两种做法

1. **推荐**：动作「用户配置」里暴露 `SY_URL/SY_TOKEN`，安装动作的用户自己填（分享到动作库必须这样做）。
