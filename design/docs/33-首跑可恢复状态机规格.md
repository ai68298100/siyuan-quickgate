# 33 · 首跑可恢复状态机规格（L562 · G2-01 增强）

> 2026-10-07。规格先行（E2）。**实现绑定门槛：首跑向导真实使用反馈**（design/docs/25-observation.md）——规格不定实现日期；实现时按本文验收，行为变更须回写本文。
> 现状基线：v0.7.5 + 工作区增量（R288 向导 / R330~R341 打磨）的 `renderWizard`。

## 1. 目标与非目标

**目标**（来自 TODO L562）：首跑七步「环境检查 → 选择能力 → 桥权限 → 连接探针 → 样例只读 → 可选样例写入 → 完成」；**刷新/关闭设置面板后可续上**——不强迫用户从头再来；每步真实探针，失败给「重试 / 改配置 / 查看 FAQ」三路径。

**非目标**：
- 不改变三通道语义与安全模型（桥默认关、写命令确认门控、幂等台账——全部不动）。
- 不做向导的多方案/主题定制。
- 不新增任何外部面（向导用到的探针全部是已有只读 op 与面板内能力）。
- 不做"跳过检测强进下一步"——每步通过条件即真实条件。

## 2. 状态模型

### 2.1 步骤定义（七步）

| # | 步骤 | 通过条件（真实探针） | 失败三路径 |
|---|------|----------------------|-----------|
| 1 | 环境检查 | `/api/system/version` 可达 + 桥目录可读（现状探针保留） | 重试（重新探测）/ 改配置（连接页）/ FAQ |
| 2 | 选择能力 | 用户勾选 ≥1 项意图能力（默认勾选「外部自动化」；勾选仅影响后续步骤的提示文案与推荐开关，不改变安全默认） | 可随时改选 |
| 3 | 桥权限 | 用户对 `bridgeEnabled` 显式表态（开或"暂不，用不开桥路径"）——表态即持久化 | 返回上步改选能力 |
| 4 | 连接探针 | `bridge.ping` 自检通过（现状 runPing 保留 + 耗时/证据复制 R333 已有） | 重试 / 改配置 / FAQ |
| 5 | 样例只读 | `daily.status` 或 `editor.context` 任一只读探针返回（显示结果+耗时+通道；L564 证据格式） | 重试 / FAQ |
| 6 | 样例写入（可选，默认跳过） | 快速捕获测试块写入 + 展示块 ID + **一键撤销**（R337 撤销写入复用） | 跳过即视为通过；撤销失败给块 id 手工处理 |
| 7 | 完成 | 1~5 全过（6 可选）→ 写完成标记 | — |

### 2.2 持久化载体：`wizard-state.json`

- 路径：`/storage/petal/siyuan-quickgate/wizard-state.json`（插件自身存储，非桥载体）。
- 形状：`{ schemaVersion: 1, startedAt: ISO, currentStep: 1..7, stepResults: { env: "ok"|"err", capability: string[], bridgeDecision: "on"|"defer", ping: "ok"|"err", pingEvidence: string, sampleRead: "ok"|"err"|"skipped", sampleWrite: "ok"|"undone"|"skipped" }, completedAt: ISO | null }`
- **写入时机**：每步状态变更即整文件覆写（文件 <1KB，频率低，无 O(N) 问题——L604 边界自查通过）。
- **完成语义**：`completedAt` 写入即首跑结束；后续打开设置一律显示状态概览（不再进向导），`wizard-state.json` 保留作审计痕迹（不删除）。
- **与 settings 的关系**：`bridgeEnabled` 等真实开关仍存 `bridge-settings.json`（现状不变）；wizard-state 只存**向导进度与证据**，不复制开关值（避免双写者竞态——R78 教训）。

### 2.3 恢复规则

| 场景 | 行为 |
|------|------|
| 打开设置，wizard-state 存在且 `completedAt` 为空 | 渲染到 `currentStep`；已完成步骤显示历史结果（绿勾+时间），可点重跑 |
| wizard-state 不存在且 settings 为出厂默认（现状 firstRun） | 从步骤 1 开始（与现状一致） |
| wizard-state 存在但 settings 已非默认（用户手动开过桥） | 视为放弃向导：提示「检测到桥已在运行——向导已完成环境部分」，落状态概览 |
| `completedAt` 非空 | 永久不进向导 |

| 步骤 | 数据来源（全部已实现能力，零新增外部面） | UI |

## 4. 边界与失败语义

- **每步失败不阻塞后续可见性**：失败步骤显示原因+三路径，其后步骤显示"待前序通过"（现状 dimmed 语言）。
- **并发**：向导打开期间桥循环照常（wizard-state 只被设置面板读写，无第二个写者）。
- **降级**：wizard-state 读失败（损坏）→ 按不存在处理从步骤 1 开始，并在步骤 1 卡内提示"向导进度损坏已重置"（不明默默态）。
- **移动端**：向导同样可用（探针相同）；桥权限步的移动端 opt-in 文案需出现（现状 isMobileGuard 文案）。
- **安全**：全部探针只读；样例写入默认跳过且可撤销——零强制写入。

## 5. 验收标准（实现时逐条对勾）

1. 首跑进行到任意步关闭设置面板 → 重开 → 停留在原步骤，已完成步骤带历史结果。
2. 刷新思源（内核重启）→ 重开 → 同上（wizard-state 在内核存储，天然跨重启）。
3. 每个失败步骤可见「重试 / 改配置 / 查看 FAQ」三路径且全部可点可达。
4. 样例写入默认未勾选；执行后撤销成功 → 块从文档消失 → 向导记 `undone` 并判通过。
5. 完成后再打开设置 → 状态概览（非向导），wizard-state 保留 completedAt。
6. 全程零新增外部面（对照 §1 非目标）；安全默认不变（桥仍默认关）。

## 7. 开放问题（实现前需定）

1. 步骤 5 样例只读用 `daily.status` 还是 `editor.context`？——建议 daily.status（无编辑器依赖，手机也可用）；editor.context 作为桌面备选。
2. `bridgeDecision=defer` 用户后续手动开桥 → 向导是否复活提示？——建议：状态概览「下一步」文案给"继续首跑向导"链接（soft nudge，不强进）。
3. wizard-state 与"恢复默认设置"的交互——建议：恢复默认时一并删除 wizard-state（回到完整首跑），并受防线备份保护（R338 语义）。
