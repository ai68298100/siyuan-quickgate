# 整体评审与优化：插件 × 动作 × 思源融合

> 评审日期：2026-10-01，2026-10-02 追加生态中枢范围收敛。范围：思源超级面板（05）、具体动作集（03）、小驴快门（06）、桥协议（02）作为整体系统。
> 方法：按「定位 / 功能 / 交互 / 融合 / 工程」五个维度过堂，每项优化给出问题、方案、影响面与去向；末尾含「评审后维持不变」的决策记录。
> 本轮核实的新事实：`/api/system/getConf`（无参读全局配置）、`/api/notebook/getNotebookConf`（读笔记本配置，含日记路径）、`/api/ai/chatGPT`（复用思源内置 AI）三个端点可用——支撑 O3/O6。

## 0. 总体判断

架构方向正确（面板+单点动作+快门网关三层），但有**一个结构性冗余**和**一组交互盲区**：

1. **结构性冗余（O1，本轮最重要发现）**：02 桥协议要求打卡/人脉各自实现 NDJSON 轮询器，但这两个插件**已经有公开窗口桥**（`window.siyuanCheckin` v5 / `window.LvContacts` v1）。快门在窗口内，可以直接转发调用——逐插件桥接是绕远路。
2. **交互盲区**：外部动作只知道「选中了什么文本」，不知道「思源里当前打开哪个文档、光标在哪个块」——导致「摘到当前文档」「当前块转待办」这类最自然的操作做不了。
3. **配置负担**：目前要求用户手填日记笔记本 ID、收集箱文档 ID——这些思源配置里本来就有（日记路径在笔记本 conf），应该自动发现。

## 6. 评审后维持不变的决策（防反复）

1. **NDJSON 仍是快门 v1 传输**：广播通道（v1.5）与内核路由（v2）只在延迟实测不可接受后启动——不为 300ms 提前付复杂度。
2. **showmenu 仍是首选 UI**：等实测项 A 结果，不预降级到 ReactUI。
3. **不做备份动作**（T17）、**不做清理动作的写模式**（SY-13 只读）——边界不改。
4. **超级面板 L1/L2 纯内核零依赖**的降级线不动。
5. 668 `/api/exec` 只用于手机→PC 方向；PC 内反向触发先走快门/桥（CORS 未实测前不押注浏览器直调）。
