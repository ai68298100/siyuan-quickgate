# 32 · 用户结果卡（核心动作 · L545）

> 2026-10-07。按用户结果排列（L545 要求），每张卡固定六问：**用户问题 → 输入 → 输出 → 写入位置 → 证据 → 失败恢复**。
> 行为基准 = v0.7.5 + 工作区增量（R330~R341 后的 `dist/`）。所有卡片只写已实现事实；未验证处显式标注，不把目标当实测（E 证据等级按 R123-G0 口径）。
> 通用前提：桥默认关；写命令经确认门控（30 秒超时=拒绝）；全部执行入审计（`audit.json`，上限 200 条）。

## 第一梯队：一句话记东西

### 卡 1 · 快速捕获（一句话进日记/收集箱）
- **用户问题**：手头有句话，想 3 秒内记下来，不想翻日记。
- **输入**：一句话文本（命令面板输入即所得）+ 去向（今日日记 / 收集箱，二选一）。
- **输出**：思源里多一个块；成功卡显示确切的块 ID 与文档 ID，可「打开原文 / 复制块引用 / 再记一条 / 撤销写入」。
- **写入位置**：今日日记 → 追加 `- HH:mm 原文`（appendDailyNoteBlock）；收集箱 → 纯文本追加到收集箱文档（appendBlock）。
- **证据**：成功卡的块 ID 可在思源中直接定位原文（E4 真机）；写入前有格式预览（与落盘逐字一致）。
- **失败恢复**：误捕获 → 成功卡「撤销写入」（deleteBlock 删刚写入块，二次确认）；写失败即无半写入垃圾（append 不可分割）；目标缺席时明确报错并给建收集箱指引，不静默换目标。

### 卡 2 · 打卡记录 / 概览（checkin.record / checkin.summary）
- **用户问题**：不打开打卡插件就记一条打卡、看今日完成度。
- **输入**：itemId（必填，checkin.items 可查）+ 可选 value/note；概览无输入。
- **输出**：recorded 回执 + 打卡插件自身消息（如「已记录：英语晨读 ×1（连续 12 天）」）。
- **写入位置**：**打卡插件的数据**（经其公开桥 window.siyuanCheckin v5，快门不直接写打卡存储）。
- **证据**：results.ndjson 回执行（status=recorded + elapsedMs）＋打卡插件界面可见（双重可验证）。
- **失败恢复**：failed → 恢复中心换新 id 重试；rejected（确认超时/黑名单）→ 按原因处理；duplicate → 幂等已跳过，无需操作。
- 证据等级：E4（真机多轮）。

### 卡 3 · 人脉搜索 / 记录互动（contacts.search / contacts.interaction / contacts.ensure）
- **用户问题**：见某人后记一笔互动，或找联系人。
- **输入**：搜索关键词；互动需联系人 id + 备注（ref/date/place/note 可选）。
- **输出**：搜索命中列表；互动 recorded 回执。
- **写入位置**：人脉插件数据（经公开桥 window.LvContacts v1）。
- **证据**：同卡 2（回执 + 人脉插件可见）。
- **失败恢复**：同卡 2。证据等级：E4。

## 第二梯队：把命令交给插件

### 卡 4 · 执行任意插件命令（commands.run / registry.list / commands.list·search）
- **用户问题**：不翻菜单，直接执行某插件的某条命令（含快捷键没绑的）。
- **输入**：plugin + command（命令面板条目可一键「{} 复制命令信封」拿到现成 JSON）。
- **输出**：宿主执行该命令（与用户手动点菜单完全等价）。
- **写入位置**：由目标命令自身决定（快门只触发，不代写）。
- **证据**：审计行（time/plugin/command/status/elapsedMs）＋命令面板「{}」信封可复现同一次调用。
- **失败恢复**：确认超时=拒绝（rejected）；插件缺席/黑名单=unsupported/rejected，均有原因文案。
- 证据等级：E4。

### 卡 5 · 收藏与最近使用（favorites.add / favorites.list / favorites.remove）
- **用户问题**：常用命令置顶，下次面板秒达。
- **输入**：plugin/command/title。
- **输出**：面板条目 ★ 置顶（去重前移）、最近使用自动排前。
- **写入位置**：`/storage/petal/siyuan-quickgate/favorites.json`（独立于桥文件）。
- **证据**：面板可见 + 载体明细卡可见该文件行数。
- **失败恢复**：条目 ☆ 移除或收藏对话框移除；「清空全部最近使用」带确认。
- 证据等级：E4。

### 卡 6 · 从模板建文档（template.new）
- **用户问题**：按模板一键建文档。
- **输入**：notebook + hpath + 模板（template/templatePath 二选一）。
- **输出**：新文档。
- **写入位置**：指定笔记本指定路径。
- **证据**：回执 + 思源文档树可见。
- **失败恢复**：路径穿越被守卫拦截（path-guard 白名单），失败回执给原因；不产生半写入。
- 证据等级：E4（守卫矩阵七用例×双通道测试 E3 + 真机）。

## 第三梯队：看状态、找问题

### 卡 7 · 打开文档 / 今日日记状态（doc.open / daily.status）
- **用户问题**：从外部（Quicker/手机）直达某文档；或先问「今天日记建了没」。
- **输入**：doc id；日记状态无输入。
- **输出**：思源打开对应页签；日记状态返回 docId/exists。
- **写入位置**：无（只读/导航）。
- **证据**：思源界面本身；docId 可交叉验证。
- **失败恢复**：文档不存在 → failed 回执带 id 原文（回执中心可查）。
- 证据等级：E4。

### 卡 8 · 生态发现与诊断（registry.list / diagnostics.report / config.discover）
- **用户问题**：装了哪些插件、哪些命令可用；出问题时给 AI 助手/自己一份可贴的体检报告。
- **输入**：无。
- **输出**：清单（成熟度×实装版本）、脱敏诊断 JSON（设置+统计+审计尾 50）、日记笔记本+收集箱自动发现结果。
- **写入位置**：无（只读；诊断只进剪贴板，复制前有预览）。
- **证据**：诊断包各字段可在设置页交叉核对。
- **失败恢复**：探测失败给原因与重试；桥关时内核路由子集仍可用。
- 证据等级：E4。

### 卡 9 · 受控编排（workflow.plan / workflow.execute）
- **用户问题**：把几步串成一次执行。
- **输入**：步骤计划（≤8 步、白名单 op）。
- **输出**：计划 → 整份确认 → 逐步执行 → 回执。
- **写入位置**：各步 op 各自的写入位置（受各自门控）。
- **证据**：每步回执；失败即停不回滚（语义如实）。
- **失败恢复**：失败步骤按 op 恢复卡处理；确认超时=整单拒绝。
- 证据等级：E4（真机走查）/ 取消语义 pending（L572）。

## 第四梯队：守护数据

### 卡 10 · 全量备份 / 恢复（面板）
- **用户问题**：动手前留底；换机/试错后能回来。
- **输入**：无（导出）；备份文件 + 分组勾选（导入）。
- **输出**：单 JSON（设置+收藏+审计+回执+台账，含 schemaVersion）；导入后逐组生效。
- **写入位置**：下载目录（导出）；五载体（导入所选组）。
- **证据**：导入对话框差异摘要（设置 diff 键名、各组条数）可预核对。
- **失败恢复**：重置/导入前自动备份防线；重置后本会话内可一键撤销；设备名永不随备份迁移。
- 证据等级：E4（roundtrip e2e 10 项 + 靶场端到端）。

### 卡 11 · 事件查看（events.list / events.pull）
- **用户问题**：打卡记录/删除事件有没有被快门如实转交。
- **输入**：白名单过滤。
- **输出**：事件行（记录与删除标记共存）。
- **写入位置**：`/storage/petal/siyuan-checkin/bridge/events.ndjson`（快门代打卡物化）。
- **证据**：载体明细卡可见该文件行数；删除标记按幂等键与原行配对。
- **失败恢复**：高频事件（analytics-updated）被明确排除（D-0011），不挤占窗口。
- 证据等级：E4。

## 三通道一句话（细节见 README/api.md）

同一个信封、共用一份幂等台账：NDJSON 桥（默认主路径，~750ms）｜内核同步路由（~100ms，桥关时 7 只读 op 仍可用）｜广播快路径（~10–100ms，默认关）。面板里的命令与这里的动作同源——面板「{}」复制的信封就是外部客户端发的同一条命令。
