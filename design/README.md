# 小驴快门动作：Quicker × 思源笔记联动中枢

> 这是一份 Quicker 动作设计、模板和产品规划仓库，围绕“小驴快门”整理动作蓝图、桥接协议、界面原型、AI 提示词和待办，不等同于快门插件源码仓库。
>
> 本文区分“已发布能力、实验能力、规划能力”；规划项不会随当前安装包自动获得。

## 一句话定位

**小驴快门是小驴生态的可信意图路由器**：把来自 Quicker、思源、快捷键、手机、脚本、MCP 或 AI 的“我想完成某件事”，转成可解释、可确认、可核验、可恢复的任务结果。

它让不同入口使用同一套能力发现、上下文、权限、幂等、回执和恢复规则。业务事实仍由小驴雷切、打卡、拾遗、人脉、管家、闪卡、考试等插件持有；快门负责把这些能力安全地串起来。

## 30 秒看懂

以下是产品目标与规划使用逻辑；当前已发布、实验和规划能力的边界见下方状态表。

- **快速捕获**：把当前选区或一句话送入收件箱、日记或其他明确目标。
- **统一命令**：从一个入口发现已安装插件的能力，并说明来源、权限和降级路径。
- **可恢复执行**：执行前看到计划和影响，执行后拿到业务回执；未知时可以查询、等待、人工核对或安全放弃。
- **AI 辅助**：帮助理解意图、选择上下文、生成只读研究或草稿；写入仍需确认。
- **Quicker 联动**：Quicker 负责动作编辑和运行，快门负责跨插件路由、权限、回执和业务核验。

核心闭环：

~~~
意图 → 上下文 → 计划 → 确认 → 执行 → 回执 → 核验 → 恢复/复用
~~~

## 用户能得到什么

| 用户关心的问题 | 快门提供的结果 |
|---|---|
| 你理解了我要做什么吗？ | 可编辑的目标、对象、范围和约束 |
| 会读写哪些内容？ | 上下文来源、读写范围、外发字段和权限说明 |
| 接下来会发生什么？ | 带 owner、风险、依赖和替代路径的计划 |
| 真的做完了吗？ | 业务插件回执、证据、时间和结果状态 |
| 出错或没回执怎么办？ | 查询原结果、等待、人工核对、补偿或重新发起 |
| 下次还能复用吗？ | 保存为任务配方、AI 模板或 Quicker 动作 revision |

## 适合谁

- 经常在思源中捕获、查找、整理和复盘，希望减少重复操作的人；
- 已经使用 Quicker，想把桌面快捷动作接入思源和小驴插件的人；
- 使用思源 Agent、外部 MCP 或脚本，希望请求有范围、有确认、有回执的人；
- 维护小驴插件、需要公开能力和联动契约的作者。

如果只想使用一个独立记事工具、不需要跨插件联动，或不接受本地权限确认和结果核验，快门不是合适的入口。

## 三条最小用户路径

### 快速捕获：选中内容 → 收件箱

1. 从思源选中内容，通过快捷键、Quicker 或面板发起“保存到收件箱”。
2. 快门显示来源文档、选区、目标收件箱和是否附带链接。
3. 用户确认后执行，返回收件箱块 ID、时间和原文回链。
4. 若回执迟到或目标不可用，任务进入恢复中心，可查询、等待或人工核对。

### 业务查询：今天要处理什么

1. 用户输入“今天还有哪些打卡和待办”。
2. 快门按公开能力查询，不把不同插件的业务口径混成一个数字。
3. 结果卡标出来源、数据截至时间、缺失插件和可继续动作。
4. 用户可打开原插件、保存查询或生成下一步草稿。

### AI 只读研究 / Quicker 动作草稿

1. 选择文档、块、附件或历史回执，逐项检查上下文和敏感字段。
2. AI 生成引用明确的研究摘要、任务草稿，或根据目标生成 Quicker ActionSpec。
3. 草稿先经过 schema、权限和依赖检查，写入和分享仍需用户确认。
4. 运行结果以业务回执核验，再保存为模板或动作 revision。

## 入口和分工

| 入口 | 适合的使用方式 | 快门统一保证 |
|---|---|---|
| Quicker | 快捷键、按钮、动作组合、桌面自动化 | 参数、权限、幂等、回执和失败恢复 |
| 思源面板/命令 | 在当前文档、块或选区上操作 | 当前上下文、计划预览和结果回链 |
| 思源 Agent / AI | 用自然语言研究、整理或生成草稿 | 上下文选择、工具白名单、确认和事实引用 |
| MCP、脚本、手机 | 从外部设备或自动化流程触发 | 能力发现、身份、跨端续接和降级解释 |

入口可以不同，用户看到的任务、确认、状态和结果语义应保持一致。原始操作名、桥协议和 schema 只在诊断或作者模式中展开。

## 快门与 Quicker 的关系

Quicker 有自己的动作编辑器、变量/模块/子程序、暂存区、试运行、运行分析和 AI 创建能力。快门不替代这些能力，而是提供动作与思源/小驴生态之间的可靠运行契约：

1. **在 Quicker 中设计**：确定触发器、输入输出、模块和用户可见结果。
2. **由 AI 辅助起草**：根据目标生成动作草稿、参数说明和测试夹具；草稿必须经过静态审查。
3. **交给快门预览**：展示将读、将写、外发、依赖、权限和业务 owner。
4. **暂存与试运行**：先在 Quicker 暂存区或 dry-run 中验证，再由真实业务回执确认效果。
5. **形成可维护 revision**：记录动作版本、环境、依赖、证据和回滚路径，再决定是否分享。

本项目进一步把 Quicker 定位为桌面/浏览器的输入与执行层：网页列表、富剪贴板、截图/OCR、Office 选区、文件索引、开发工具证据和思源反向调用都先进入预览与确认，再写入思源或对应业务 owner。具体动作卡片、版本门槛和失败出口见 [Quicker 增强思源动作场景调研 R151~R160](docs/22-Quicker增强思源动作场景调研-R151-R160.md)。

HTTP 200、动作保存成功或 AI 生成完成，都不等于业务完成；只有业务插件返回可核验的回执，结果才可标为 verified。

## AI 能力和边界

AI 是能力层，不是授权层。它可以帮助用户和作者：

- 从自然语言提取意图，提示缺少的对象、时间或范围；
- 根据当前上下文生成只读研究计划、摘要、引用和任务草稿；
- 根据 Quicker 目标生成动作规格、模块建议、参数表和测试夹具；
- 解释失败、整理诊断、给出恢复方案和人工替代路径；
- 根据历史结果推荐可复用的任务配方或提示词模板。

AI 默认遵循四条边界：上下文逐项选择、外发逐字段预览、写入分层确认、结果以业务回执为准。模型的肯定语气不能代替用户授权；模型不可用时，原始任务仍应能保存、只读查询或转人工处理。

当前需要区分三种 AI：

- **思源 Agent**：原生接入和内置提示词仍属于待验证/规划能力；
- **外部 MCP 或脚本**：按公开桥和能力白名单接入，默认以低风险、可审计调用为主；
- **Quicker AI**：帮助创建或修改动作草稿，必须经过 Quicker 暂存、静态审查、试运行和业务核验。

## 当前能力状态

| 状态 | 事实与边界 |
|---|---|
| 已发布/已有工程记录 | 快门实现仓库为 [ai68298100/siyuan-quickgate](https://github.com/ai68298100/siyuan-quickgate)，当前记录版本 v0.7.1；CI、单测和若干本机 spike 已有记录。当前安装包提供设置、桥/诊断和协议能力，具体可用项以能力目录和回执为准。 |
| 实验/等待真机证据 | 多工作区、端口/令牌发现、广播快路径、重启后的桥存活、MCP、事件工作流和真实插件回执仍需按清单复测。 |
| 规划 | 统一任务首页、意图/计划/结果/恢复中心；AI 工作台和内置提示词模板；Quicker 动作作者工作台和发布预检；权限、隐私、通知、跨设备续接、无障碍和性能治理。 |

小驴各插件的公开能力、事件和 owner 逐项校准；没有契约证据的模块只进入设计或只读预览。规划页面不会自动变成当前安装包的功能。

## 安全与数据边界

- 桥默认关闭；启用后仍按 allowlist、令牌、确认和审计执行。
- 快门只依赖插件公开注册的能力和桥方法，不读取其他插件的私有存储，也不自行重算业务口径。
- AI 规划要求本地执行与模型外发分开显示、外发前逐字段预览；当前尚未实现 AI 工作台，真实模型/host 的数据边界以其配置和授权为准。
- 插件缺席、未初始化、版本不兼容或桥不可达时，显示具体原因、影响和替代路径，不把“暂时不可用”伪装成“没有数据”。
- 意图、计划、回执、审计和关系索引属于快门的编排记录；文档、打卡、联系人、卡片等业务事实仍归对应插件。
- 快门不绕过用户确认，不替代思源编辑器或 Quicker 动作编辑器，也不拥有业务插件的最终事实。

## 安装与首跑（约 3 分钟）

1. 从 [GitHub Releases](https://github.com/ai68298100/siyuan-quickgate/releases) 下载与思源版本匹配的发布包，按发布说明导入并启用插件。
2. 打开快门设置，确认当前工作区、内核连接、令牌和能力发现状态；产品默认端口按思源环境使用 6806，本机实验覆盖的其他端口不要直接复制到用户配置。
3. 外部命令桥默认关闭。先按调用通道检查：已有内核同步路由的只读能力可在桥关闭时使用；NDJSON/广播或依赖前端消费的路径才需要相应开关。MCP 写入授权与桥开关分开。
4. 当前先按已验证能力做只读探针，再按动作蓝图自建一条低风险测试动作并核对业务结果。统一计划/结果工作台属于规划，安装包尚不能按原型直接走完整页面流程。
5. 首跑失败时保留诊断信息，先走设置页的探测/解释/修复/复测，再决定是否重试；不要把失败任务静默清掉。

安装包中未包含本仓库所有规划页面、AI 模板或 Quicker 动作草稿；这些内容需要按文档和版本门禁逐步启用。

## 推荐的首次使用路径

1. 阅读 [使用手册](docs/11-使用手册.md)，在状态页确认工作区、端口、令牌和桥状态。
2. 先用一条低风险、可核验的“捕获到收集箱”路径，确认能力发现、计划预览、执行和回执。
3. 再尝试 AI 只读研究或草稿生成，逐项检查上下文和外发字段。
4. 最后按 [Quicker 动作编辑与 AI 创建调研](docs/17-Quicker动作编辑与AI创建调研-R106-R113.md) 创建、暂存、试运行和核验动作。
5. 遇到问题先看 [故障排查 FAQ](docs/12-故障排查FAQ.md)，再复制脱敏诊断；不要凭 HTTP 状态码判断业务成功。

## 设计和开发前的原则

- 先确认用户结果和业务 owner，再决定调用哪个接口。
- 先做只读、预览和可恢复路径，再开放写入和后台自动化。
- 计划可编辑，确认有范围和有效期，写入使用幂等键，结果必须有回执。
- unknown、部分成功和迟到回执必须显式进入恢复中心，不能静默结束。
- AI、Quicker、MCP 和手机只是入口或协作者；授权、审计和最终事实由快门与业务插件共同守住。

本轮只做调研、文档和待办整理，没有修改实现仓库、没有接入真实模型，也没有改变真实 AI 配置。
